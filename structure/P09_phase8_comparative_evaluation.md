## 1. 이 단계에서 답할 질문

소수 미국 기업의 같은 입력과 검토 예산에서 중요한 사건과 필요한 사업 관계를 근거에 맞게 보존하고, 사람이 기존 상태의 변화·추가 확인 사항을 이해하며 검토량·시간·API 비용을 줄일 수 있는가?

- **책임 역할 후보:** C 실험 설계·분석, B 재현 실행·비용, A 사용자 과업·오류 검토. A/B/C는 미배정 역할 자리이며 기업별 담당이나 인원 수를 확정하지 않습니다.
- **착수 조건:** 미국 자료로 새로 구성한 P3 평가 manifest, P4/P5/P6 고정 모델·정책, P7 고정 MVP. 테스트를 본 뒤 평가 목적이나 운영점을 바꾸지 않는다.
- **범위:** 비교군·ablation·시간/기업 검증·사용성·비용·오류 보고. 실제 자원·권리·예산에 따라 실행 군을 사전 선정하며 미실행 유료 비교군은 추정 수치로 대체하지 않는다. 투자 수익률 개선은 개인 동기이며 프로젝트 KPI나 보장 성과가 아니다.
- **연결 에픽:** [KAN-12](https://qyurimoon.atlassian.net/browse/KAN-12)은 기존 작업 연결 참고입니다. 새 대상의 담당·기한 배정은 별도 결정합니다.

## 3. 상세 설계와 판단 규칙

### 비교군과 동일 조건

S0 시간순 원문 목록, S1 키워드/규칙 필터, S2 전통 ML, S3 로컬 NLP 파이프라인, S4 로컬+선택적 LLM, S5 전체 LLM 처리. 모든 군이 같은 extraction 기능을 제공하는 것은 아니므로 전체 검토 효용과 기능별 성능을 분리한다. 같은 입력 manifest·발표 cutoff·후보 universe·검토 budget을 사용한다. 여러 LLM 모델·prompt를 test에서 탐색하지 않는다.

비교군 목록은 설계 후보이며 모두 구현·실행하겠다는 확정이 아니다. 무료 자료와 보유 자원에 맞는 baseline부터 시작하고, 외부 API·LLM 비교는 저장·AI 입력·외부 전송 권리와 비용 근거를 확인한다. 미국 영어 원문과 같은 범위의 근거 접근 조건을 사용한다. 한국어 검토 요약을 제공하는 조건은 별도로 명시하고, 요약의 이해 편의와 원문 추출 정확도를 구분한다.

### 중요 사건 보존과 검토 부담

reference universe는 평가기간에 수집·라벨링한 전체 대상 사건이다. 필터 탈락을 포함한 end-to-end important recall, reviewed fraction, 중요 사건1건당 검토시간, 수정률을 함께 보고한다. ‘필터를 통과한 것 중 recall’만으로 업무 절감 효과를 주장하지 않는다. 공개 문서가 수집에서 누락된 경우 coverage 한계도 별도 공개한다.

개체·사업 관계는 방향·상대·제품/사업 범위·상태·적용 기간·원문 근거의 일치율을 따로 측정한다. 관계가 원문 주장에 맞게 추출되었다는 결과와 실적 영향 assessment의 적절성, 계산의 입력/수식 정확성은 다른 평가다. 검토 카드의 `review_readiness=supported / needs_review / not_comparable`와 이유가 근거 충분성·비교 조건에 맞는지도 확인한다. supported는 원문이 지지한다는 상태이며 원문 밖의 사실을 검증했다는 의미가 아니다.

### 사람 실험

같은 사람이 같은 사건을 먼저 원문으로 보고 나중에 카드로 보면 기억 효과가 있다. 난이도·유형이 유사한 서로 다른 세트를 만들고 순서를 교차 배정한다. 원문만/카드 조건을 익명화할 수 없더라도 답안과 결과를 미리 보여주지 않는다. 실제 참여자 수와 영어 원문 이해 수준을 기록하며 소규모 팀 사용성 결과를 큰 모집단의 유의한 개선으로 일반화하지 않는다. 시작/종료·원문열기·수정·중단·추가조사 이벤트를 기록하고 idle 처리 규칙을 사전에 정한다.

독립 작성자끼리의 조정 전 일치도, 시스템의 추출·연결·비교 정확도, 사람이 카드를 이용해 내린 최종 검토 판단을 분리한다. 판단하기 어려운 사례는 unresolved로 보존한다. 교차검증한 표본의 합의가 모든 문서·미공개 관계의 정확성을 보장하지 않는다. 참여 조건의 6개월 이상·주당 약 30시간은 제안자의 개인 가용 조건이며 팀 일정이나 실험 인력 예산으로 환산하지 않는다.

### 비용과 속도

문서1000건당 API 비용·호출·token·wall time을 동일 정규화 분모로 보고한다. 실제1000건을 처리하지 않았다면 관측 건수와 환산치를 함께 표시한다. 설치/모델로드/index 구축 같은 초기 비용과 warm steady-state 처리 비용을 분리한다. 실패·재시도·캐시·fallback 호출을 포함한다. 요금표 확인일·currency를 기록하고 미실행은 NA다.

1000건은 비용 정규화 분모이며 확보 표본·처리량 목표가 아니다. 무료 경로도 실제 하드웨어·메모리·실행시간을 기록하고 상시 운영 무료 가능성을 추정하지 않는다. USD 등 실제 청구 통화와 원화 환산이 있으면 환율 출처·기준일을 구분한다.

### 신뢰구간·표본 제약

문장 단위 bootstrap은 같은 사건의 상관을 무시할 수 있으므로 사건 family 또는 날짜 그룹으로 재표집하는 방법을 검토한다. 쌍을 이룬 비교는 같은 입력의 차이를 분석하고 mean/median·분포·신뢰구간을 보고한다. 다수 metric·ablation 탐색으로 나온 우연한 개선을 확정적 결론으로 쓰지 않는다. positive0·검색 정답 없음·시간 측정 누락은 분모와 함께 처리한다.

### 최종 결론의 조건

목표 recall 하한과 허용 검토량·비용·정확성 기준은 작은 미국 실제 표본과 dev 결과를 확인한 뒤 test 이전에 결정한다. 목표 수치를 지금 임의로 연구 성과처럼 적지 않는다. ‘개선’, ‘트레이드오프’, ‘근거 부족’, ‘실패’ 모두 가능한 결론이다. 회수율을 떨어뜨려 얻은 검토시간 절감은 함께 드러낸다. 미국 기업 A/B 등 새 대상에서 정의·규칙·모델을 조정하는 데 사용한 자료는 adaptation이며 순수 미노출 기업·기간 평가와 구분한다.

원문의 회계연도·실제 기간·시간대/DST·통화·scale·전사/segment·GAAP/non-GAAP 정의가 다른 사례는 호환성과 근거가 있는 정규화·변환 조건을 평가한다. 조건을 충족하면 비교 또는 조건부 비교로, 비호환이거나 필요한 입력이 없으면 비교 불가·미확인으로 이유를 남긴다. 사후 시장 반응은 별도 보조 분석으로만 사용하며 중요성 정답·과거 시점 feature·직접 수익률 KPI로 사용하지 않는다. 관계 연결만으로 실적 영향이나 다단계 인과를 확정한 결과는 오류 사례로 남긴다.

최종 보고서는 온톨로지 정의를 실제 자료에 적용하며 바꾼 이유, NLP 오류와 개선, 근거를 따라 시장 흐름을 해석한 범위와 한계를 설명한다. 별도 기업 발굴 제품이나 투자 추천 성과를 완료 조건으로 추가하지 않는다.

### 공통 성과와 개인 수행 경험의 별도 평가

[공통 목표·리서치 적용 흐름](GOALS_AND_RESEARCH_WORKFLOW.md)에 따라 온톨로지 정의·관계 규칙 적용/수정, NLP 오류 개선·미노출 정확도, 근거 있는 사업/시장 해석, 카드 효용·비용의 공통 평가를 유지한다. 개인 적용은 개념 설명·원문 비교·수식/대사·사업/재무 연결·가정/메모 수정·실제 기여를 별도 rubric으로 검토한다.

`learning_cases.jsonl`에 참여자별 수행 영역·원본 작업·오류와 수정·agent 열람 이력·검토 의견을 연결한다. 재무 적용 담당은 직접 계산·분석·가정 갱신을 설명하고 다른 참여자는 실제 맡은 온톨로지/NLP/사업 분석 작업을 설명한다. 모든 팀원에게 금융 산출물을 요구하지 않는다. 수치 계산의 검증과 해석의 근거 적절성은 다른 결과이며 개인 적용 미완료는 공통 시스템 성능과 합산하지 않는다. 실제 평가 사례 수·미완료·노출 범위와 한계를 함께 보고한다.

### P09-T04 · 사건·관계·비교 benchmark 실행

- **책임·검토:** B, C 집계

- **R03 · [Artstein & Poesio (2008), Inter-Coder Agreement](https://aclanthology.org/J08-4004/)** — 라벨 유형별 일치도·우연 일치·단위 분리 문제 검토. 확인 수준: 서지·초록 확인; 분석식 선택 전 본문 읽기.
- **R07 · [Thakur et al. (2021), BEIR](https://arxiv.org/abs/2104.08663)** — 희소/밀집 검색 비교와 다른 도메인 평가 설계. 확인 수준: 서지·초록 확인; 우리 금융 prior-state 검색을 따로 평가.
- **R09 · [MacKinlay (1997), Event Studies in Economics and Finance](https://www.jstor.org/stable/2729691)** — 추정창·사건창·정상수익률·교란 사건을 읽고 연구 메모 작성. 확인 수준: 서지 확인; 이 조사에서 원문 본문 접근 미확인. 실험 전 원문 확보 필요.
- **T01 · [scikit-learn model evaluation](https://scikit-learn.org/stable/modules/model_evaluation.html)** — 각 metric의 분모·평균 방식·undefined 조건 확인. 확인 수준: 공식 문서 확인; 설치 버전과 문서 버전 맞추기.
- **T02 · [scikit-learn cross validation](https://scikit-learn.org/stable/modules/cross_validation.html)** — 시간 분리·그룹 분리·누수 방지 평가 설계. 확인 수준: 공식 문서 확인; 일반 TimeSeriesSplit만으로 사건 묶음 분리가 보장되지 않음.
- **T03 · [scikit-learn calibration](https://scikit-learn.org/stable/modules/calibration.html)** — 보정 곡선·확률 평가·별도 보정 데이터 운영. 확인 수준: 공식 문서 확인; 낮은 Brier만으로 보정 품질 단정 금지.
- **O03 · [W3C PROV-O](https://www.w3.org/TR/prov-o/)** — 원문→추출→수정→계산의 출처·행위·작성 주체 연결. 확인 수준: 공식 표준 확인; v1은 관계형 기록으로 구현 가능.

문헌·API를 실제 작업에 사용한 뒤 읽은 절·페이지·버전·실행일을 기록합니다. 확인한 개요와 아직 정독하지 않은 본문을 구별합니다.
