## 3. 상세 설계와 판단 규칙

### 비교군과 동일 조건

S0 시간순 원문 목록, S1 키워드/규칙 필터, S2 전통 ML, S3 로컬 NLP 파이프라인, S4 로컬+선택적 LLM, S5 전체 LLM 처리. 모든 군이 같은 extraction 기능을 제공하는 것은 아니므로 전체 검토 효용과 기능별 성능을 분리한다. 같은 입력 manifest·발표 cutoff·후보 universe·검토 budget을 사용한다. 여러 LLM 모델·prompt를 test에서 탐색하지 않는다.

### 중요 사건 보존과 검토 부담

reference universe는 평가기간에 수집·라벨링한 전체 대상 사건이다. 필터 탈락을 포함한 end-to-end important recall, reviewed fraction, 중요 사건1건당 검토시간, 수정률을 함께 보고한다. ‘필터를 통과한 것 중 recall’만으로 업무 절감 효과를 주장하지 않는다. 공개 문서가 수집에서 누락된 경우 coverage 한계도 별도 공개한다.

### 사람 실험

같은 사람이 같은 사건을 먼저 원문으로 보고 나중에 카드로 보면 기억 효과가 있다. 난이도·유형이 유사한 서로 다른 세트를 만들고 순서를 교차 배정한다. 원문만/카드 조건을 익명화할 수 없더라도 답안과 결과를 미리 보여주지 않는다. 팀원3명은 탐색적 사용성 평가이며 큰 모집단의 유의한 개선으로 일반화하지 않는다. 시작/종료·원문열기·수정·중단·추가조사 이벤트를 기록하고 idle 처리 규칙을 사전에 정한다.

### 비용과 속도

문서1000건당 API 비용·호출·token·wall time을 동일 정규화 분모로 보고한다. 실제1000건을 처리하지 않았다면 관측 건수와 환산치를 함께 표시한다. 설치/모델로드/index 구축 같은 초기 비용과 warm steady-state 처리 비용을 분리한다. 실패·재시도·캐시·fallback 호출을 포함한다. 요금표 확인일·currency를 기록하고 미실행은 NA다.

### 신뢰구간·표본 제약

문장 단위 bootstrap은 같은 사건의 상관을 무시할 수 있으므로 사건 family 또는 날짜 그룹으로 재표집하는 방법을 검토한다. 쌍을 이룬 비교는 같은 입력의 차이를 분석하고 mean/median·분포·신뢰구간을 보고한다. 다수 metric·ablation 탐색으로 나온 우연한 개선을 확정적 결론으로 쓰지 않는다. positive0·검색 정답 없음·시간 측정 누락은 분모와 함께 처리한다.

### 최종 결론의 조건

목표 recall 하한과 허용 검토량·비용은 dev 이후 test 이전에 결정한다. 목표 수치를 지금 임의로 연구 성과처럼 적지 않는다. ‘개선’, ‘트레이드오프’, ‘근거 부족’, ‘실패’ 모두 가능한 결론이다. 회수율을 떨어뜨려 얻은 검토시간 절감은 함께 드러낸다. 리노공업·ISC adaptation 이후 평가 결과는 순수 미노출 기업 결과와 구분한다.

- **실패·미해결 처리:** 실패 입력/원문 위치·시도·원인·다음 확인 역할을 결과 기록에 남깁니다. 누락을 임의 값으로 채워 완료 처리하지 않습니다.


## 5. 필수 검증 시나리오

- [ ] 필터에서 빠진 gold 중요 사건이 최종 recall의 FN으로 집계된다.
- [ ] 실제100건 비용을1000건으로 환산한 경우 환산임을 명시한다.
- [ ] P2/P7에서 본 사건을 깨끗한 test라고 표현하지 않는다.
- [ ] LLM 미실행 비교군에 추정 성능을 입력하지 않는다.
- [ ] 상위 k가 같은 날의 후보 수보다 크거나 positive0인 경우 metric 정책을 따른다.

## 6. 단계 종료와 다음 단계 전달

**종료 기준:** 동일 조건 비교표, 검토 효용·비용·불확실성·오류·재현 보고서가 완성됐고 주요 수치가 원본 실험과 연결된다. 사전 목표 미달도 그대로 최종 결과로 남긴다.

**인계:** 최종 보고서·데모·기술문서와 후속 연구 backlog. 배포나 추가 구현은 실제 요구가 있을 때 별도 범위로 정한다.

결과 기록에는 완료 작업 ID, 산출물 경로·버전·hash, 실제 건수, 검증 결과, 검토 역할, 남은 문제와 후속 작업을 남깁니다. 미실행 검증을 통과로 표시하지 않습니다. 성능 목표·예산·표본 수 변경은 [결정 기록](DECISIONS.md)에 남깁니다.
