## 1. 이 단계에서 답할 질문

- **착수 조건:** 새 미국 자료로 검증한 P1 가이드와 P2 registry 버전 고정. 이번 미국 설계에 사용한 개발 사례는 노출 이력을 기록한다. 기존 한국 자료·라벨·결과를 입력이나 검증 근거로 넘기지 않는다.
- **범위:** 미국 사건·필요한 제품/서비스·고객·경쟁·공급·산업 관계의 gold v1, 라벨 가이드, 일치도·모호성·분할 manifest. 기업·섹터·기간·문서/사건/관계 수는 P0 접근성과 실제 주석 시간을 확인한 뒤 정한다.

## 3. 상세 설계와 판단 규칙

### 표본 구성과 규모

미국 자료의 접근·권리·유형 분포와 두 사람의 주석 소요시간을 먼저 측정하고 본 표본 수·중복 비율·허용 오류 수준을 결정 기록에 남긴다. 이전 한국 기업 파일럿의 표본 목표를 미국 quota로 이어받지 않는다. 실적·계획·실행·정정·부인·반복·정성 변화·무관 문서도 포함한다. rare 유형을 추가 표집했다면 자연 발생 비율과 다르다는 점을 명시한다. 관련성 분류를 평가하려면 사건이 있는 문서만 모아서는 안 되므로 무관/관련 문서 라벨도 별도로 만든다. 문서·고유 사건·발표 family·관계 tuple·비교 가능한 주장 쌍은 각각 센다.

영문 원문을 사실·span의 기준으로 삼고, 한국어 검토 문구를 제공할 경우 별도 파생 레코드로 연결한다. 번역을 독립 사실 근거나 미노출 평가 표본으로 세지 않는다. 섹터 확장은 한 섹터의 결과만으로 승인하지 않고 새 자료·정의·표본으로 확인한다.

### 중복 평가와 역할

v1 권장 운영은 파일럿 사건과 선정한 관계 표본을 A/B가 독립 작성하고 C가 불일치를 조정하는 방식이다. 부담이 크면 최소 중복 비율을 작업 시작 전에 정하고 유형·기업·기간별 층화 표본을 확보한다. 단독 라벨 자료는 단독 작성임을 표시하며 합의 gold처럼 취급하지 않는다. 연습 표본 수는 미국 원문 난도와 실제 가용시간으로 정하며, 가이드 개발에 쓴 표본은 untouched test에 넣지 않는다. 제안자의 6개월 이상·주당 약 30시간은 개인 가용 조건이며 전체 팀의 주석량이나 일정 약속이 아니다.

### 시간·사건 그룹·기업 분리

chronological split의 날짜 경계는 실제 자료 분포를 보고 고정한다. 출처 번역본·재보도·정정 관계를 포함한 이벤트 family가 경계를 가로지르면 한쪽으로 이동하거나 boundary embargo 세트로 빼고 이유를 기록한다. 같은 사건을 훈련과 평가에 넣지 않는다. 학습 이후 발생한 prior-state 사실을 검색용 읽기 전용 기록에 추가할 수는 있지만, 해당 시점까지 공개된 원문만 쓴다. 평가 정답·수정 피드백을 학습하는 것과 구분한다.

이번 미국 범위의 P1/P2 개발에 사용한 기업·문서·사건은 adaptation 또는 practice로 표시하고 untouched test에서 제외한다. 후속 미사용 기간·사건으로 post-adaptation test를 만들고, 정말 미노출 기업 평가가 필요하면 다른 미국 기업을 별도 선정한다. 적은 기업의 Leave-one-company-out 결과는 다른 섹터나 시장 전체 일반화의 증거가 아니다. 기존 한국 기업 자료·결과는 미국 train/dev/test/adaptation 어느 집합에도 넣지 않는다.

### 라벨과 일치도

기업·숫자·단위·기간은 exact match, span은 원문 Unicode code point offset F1, 유형/등급은 해당 척도에 맞는 일치도와 혼동표를 사용한다. 관계는 양끝 개체·역할·방향·유형·scope·시점·부정·modality와 근거를 따로 비교하고 전체 tuple의 일치도도 보고한다. [R03](REFERENCES.md)을 읽고 nominal/ordinal 계수를 구별한다. 조정 후 값끼리 비교해 일치도를 부풀리지 않는다. unknown과 not_applicable을 제외하면 제외 건수·분모를 보고한다. 사람 간 일치도와 P4 시스템의 추출·연결 precision/recall은 별도 평가이며 합의가 원문 오류나 비공개 관계를 해결했다는 뜻은 아니다.

### 관계 사실과 영향 판단

변화 분석 질문에 필요한 관계만 선정한다. 제품/서비스·고객·경쟁·공급·산업 관계는 원문의 화자·양끝 개체·역할·방향·적용 범위·유효/적용 시점·부정·조건·가능성을 근거와 함께 기록한다. 단순 동시 언급을 관계로 확정하지 않으며 회사가 보고한 관계와 외부 확인된 관계를 구별한다. 관계가 존재한다는 주장과 매출·생산·시장에 영향을 준다는 평가는 각각 facts와 assessments에 둔다. 계약 축소만으로 매출 감소 규모를 정하지 않는다.

검토 카드의 review_readiness 후보 supported / needs_review / not_comparable을 evidence_status·중요성 등급과 별도로 시험한다. supported는 원문이 기록한 주장을 지지한다는 뜻이며 외부 사실 확인 완료를 뜻하지 않는다. unknown인 사실·불확실성·근거 부족·비교 조건 불일치는 이유와 추가 확인 질문으로 남기며 낮은 중요성으로 대체하지 않는다. 최종 필드와 상태 정의는 공통 규약과 가이드에서 고정한다.

### 평가자의 정보 제한

발표 시점에 존재한 자료만 평가 화면에 제공하고 이후 주가·정정·후속 실행은 감춘다. 시장 outcome은 별도 테이블로 분리한다. 자기 기억으로 알게 된 사후 정보를 완전히 제거할 수 없으면 한계로 기록한다. 중요성 ‘판단 불가’를 무시 라벨로 바꾸지 않는다.

### 사실·계산 검증과 해석 판단의 분리

[공통 목표·리서치 적용 흐름](GOALS_AND_RESEARCH_WORKFLOW.md)에 따라 재무 적용 표본도 원문 숫자·기간·회계기준·사업 범위·표/주석 위치를 독립 기록한다. 선정 계산에는 모델 결과를 보기 전 작성한 수작업 기준의 입력·수식·시점·작성자와 동료 검토를 남긴다. 직접 계산과 회사 발표 수치는 별도이고, 대사가 맞는다는 것만으로 원문·정책의 진실을 확정하지 않는다.

사업·재무 영향과 가정 수정 필요성은 assessment로 주석한다. 수치 정답, 조정 전 사람 일치도, 해석의 근거 적절성을 구분한다. 개인 연습·메모·등록부 수정에 사용한 사례는 노출을 기록하고 학습 산출물을 독립 gold나 untouched test로 바꾸지 않는다. 비정량 관계 표본도 유지한다.

## 5. 필수 검증 시나리오

- [ ] 같은 발표의 번역본·정정본이 train/test 양쪽에 존재하지 않는다.
- [ ] 일치도는 조정 이전 독립 라벨로 계산한다.
- [ ] 모델에 사후 시장 outcome이나 annotator 답을 feature로 주지 않는다.
- [ ] 이번 미국 가이드/registry 개발 자료가 untouched test에서 제외되고 기존 한국 자료·결과가 모든 활성 집합에 혼입되지 않는다.
- [ ] 고객/공급 관계 방향, 계획·부인·조건·적용 시점의 이견을 독립 원본으로 재확인한다.
- [ ] 관계 사실과 영향 판단, 사람 간 일치도와 시스템 정확도를 다른 필드·분모로 보고한다.
- [ ] 불확실·추가 확인·비교 불가 사례가 낮은 중요성이나 임의 정답으로 바뀌지 않는다.

## 6. 단계 종료와 다음 단계 전달

**종료 기준:** gold·독립 기록·조정·가이드·분할 manifest가 완성되고 평가 제외·미해결 사례가 명시됐다. 낮은 일치도는 숨기지 않고 가이드 보완 또는 해당 필드의 모델링 보류로 처리한다.

**인계:** 새 미국 P4 사건·관계 추출 benchmark, P5 중요성 표현 비교, P6 검색 정답쌍 구성에 사용한다. test를 열기 전 모델·정책을 고정하며 한국 자료의 이전 결과를 미국 기준 성능으로 보고하지 않는다.

결과 기록에는 완료 작업 ID, 산출물 경로·버전·hash, 실제 건수, 검증 결과, 검토 역할, 남은 문제와 후속 작업을 남깁니다. 미실행 검증을 통과로 표시하지 않습니다. 성능 목표·예산·표본 수 변경은 [결정 기록](DECISIONS.md)에 남깁니다.

## 7. 이 단계의 레퍼런스

- **DIR01 · [미국 기업 프로젝트 개인 제안](../docs/project_direction/us_equity_research_proposal.md)** — 소수 미국 기업·필요한 사업 관계·독립 교차검증·불확실 상태를 반영. 개인 제안이며 팀 역할·기간·표본·정확성 목표의 확정 근거로 쓰지 않는다.
- **R03 · [Artstein & Poesio (2008), Inter-Coder Agreement](https://aclanthology.org/J08-4004/)** — 라벨 유형별 일치도·우연 일치·단위 분리 문제 검토. 확인 수준: 서지·초록 확인; 분석식 선택 전 본문 읽기.
- **T01 · [scikit-learn model evaluation](https://scikit-learn.org/stable/modules/model_evaluation.html)** — 각 metric의 분모·평균 방식·undefined 조건 확인. 확인 수준: 공식 문서 확인; 설치 버전과 문서 버전 맞추기.
- **T02 · [scikit-learn cross validation](https://scikit-learn.org/stable/modules/cross_validation.html)** — 시간 분리·그룹 분리·누수 방지 평가 설계. 확인 수준: 공식 문서 확인; 일반 TimeSeriesSplit만으로 사건 묶음 분리가 보장되지 않음.
- **O03 · [W3C PROV-O](https://www.w3.org/TR/prov-o/)** — 원문→추출→수정→계산의 출처·행위·작성 주체 연결. 확인 수준: 공식 표준 확인; v1은 관계형 기록으로 구현 가능.

문헌·API를 실제 작업에 사용한 뒤 읽은 절·페이지·버전·실행일을 기록합니다. 확인한 개요와 아직 정독하지 않은 본문을 구별합니다.
