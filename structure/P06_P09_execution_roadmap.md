## 3. 진행 순서와 데이터가 필요한 지점

1. **P06 개발:** 현재 후보로 검토 사유와 목록을 만든다. 사람 gold가 없어도 개발을 진행하되, 학습된 중요성 모델이나 효과 검증으로 표현하지 않는다.
2. **P07 개발:** 이전 정보 후보·시점 필터·비교·계산 엔진을 만든다. 근거 부족으로 실제 숫자 계산이 불가능한 경우에도 이유를 출력하는 기능을 검증한다.
3. **P06 후속 갱신:** P07 변화 인터페이스가 생긴 뒤 P06에 연결한다. 기존 P06 run을 수정하지 않고 새 run·정책 버전을 만든다. 독립 dev가 없으면 feature 연결까지만 하고 효과 비교는 보류한다.
4. **P08 개발:** 위 결과를 한 실행과 검토 카드에 연결한다. 현재의 2인 접근·DB 없는 운영을 유지하면서 파일로 검토 기록을 보존한다.
5. **P09 평가:** 먼저 실제 구현에 대한 회귀·재현·오류·비용 보고를 만든다. 새로운 평가 자료와 독립 사람 판단이 준비된 경우에만 정식 성능·사용성 평가를 진행한다.

사람 주석을 기다리느라 개발을 멈추지 않는다. 다만 사람이 수행해야 하는 독립 주석·사용성 세션·동료 재실행을 agent 결과로 대신 채우지 않는다. 기존 설계서의 A/B/C는 기능 역할이므로 3명이 있다는 뜻이 아니다. 현재 사용자와 팀원, 총 2명의 실제 수행만 기록한다.

### 3.1 사람 검토를 진행할 시점 — 2026-10-06 합의

**P06~P09의 개발과 자동 검증은 현재 후보의 사람 검토를 기다리지 않고 끝까지 진행할 수 있다.** 현재 사이트의 ‘검토 필요’는 추출값·날짜·사업 범위 등을 사람이 확인해야 한다는 표시다. 통합 화면과 기능을 완성한 뒤 후보를 모아서 검토할 수 있으며, 검토 전까지는 `candidate_needs_review`와 미확인 사유를 유지한다. 후속 Phase나 자동 규칙을 실행했다는 이유만으로 검토 완료로 바꾸지 않는다.

권장 순서는 **P08 통합 검토 카드 완성 → 현재 후보 일괄 검토 → P09 정식 평가**다. P09의 자동 회귀·재현·오류·비용 검증은 사람 검토 전에도 진행할 수 있다. 일괄 검토 결과는 파일 기반 검토 이력으로 보존하고, 검증한 결과를 같은 사이트에 반영한다.

**정식 정확도·중요도 평가를 완료하려면 평가 대상에 맞는 사람 판단과 별도의 독립 평가 자료·정답을 측정 전에 준비해야 한다.** 이미 개발에 사용하거나 화면에서 본 후보를 사람이 검토해도 그 후보가 독립 test로 바뀌지는 않는다. 독립 평가 자료의 노출 여부·용도·주석 절차와 평가 조건은 P09 설계에 따라 먼저 확정한다. 사용성 평가와 동료 재실행도 실제 사람이 수행한 기록이 필요하다.

따라서 검토를 미루는 동안 개발 종료 조건을 충족한 Phase는 ‘개발 완료, 연구 평가 미완료’로 기록한다. 개발 상태 `development_ready`와 연구 상태 `not_evaluated` 또는 `blocked_missing_data`를 구분하며, 모든 Phase의 코드가 구현됐다는 이유로 정식 연구 평가까지 완료했다고 보고하지 않는다.

## 5. 공통 산출물·완료 상태

각 Phase는 `artifacts/us_equity/pN/runs/<run_id>/`에 입력 snapshot·정책·출력·검증 결과·manifest를 저장한다. `active_run.json`은 검증된 run을 가리키는 포인터로 사용하고, 이전 run과 실패 run을 보존한다. 기존 P04/P05 파일과 동결 manifest를 다시 만들지 않는다.

| 상태 축 | 허용 상태 예시 | 의미 |
| --- | --- | --- |
| 개발 | `planned / running / development_ready / failed` | 현재 범위의 코드·계약·회귀·재현 상태 |
| 연구 평가 | `not_evaluated / blocked_missing_data / evaluated` | 독립 정답·평가 수행 여부; 개발 상태와 별도 |
| 사이트 | `not_updated / preview_checked / publish_pending / published / failed` | 실제 게시 여부 |

단계 종료 기록에는 완료 작업 ID·입력/출력 hash·실제 건수·실패/보류·검증과 미실행 검증·사이트 버전과 배포 결과를 남긴다. 사이트 게시가 실패하면 ‘코드 개발 완료, 사이트 반영 미완료’로 보고하고 게시 작업을 남긴다. 연구 데이터가 없는 상태에서 개발 완료를 정식 benchmark 완료로 바꾸지 않는다.

## 6. 설계서와 이후 실행 기록의 관계

이 로드맵과 P06~P09 실행 설계서는 2026-10-06 현재 상태의 실행 기준이다. 기존 각 Phase의 전체 연구 설계와 [공통 데이터 규약](DATA_CONTRACTS.md), [공통 목표](GOALS_AND_RESEARCH_WORKFLOW.md)를 연결하되, 실제 자료로 수행할 개발과 조건부 연구 작업을 구분한다. 사용자가 요청한 웹사이트와 DB 없는 2인 운영은 이전 문서의 ‘웹서비스 비필수’·DB 제안을 갱신하는 최신 요구사항이다.

현재 작성 작업은 설계 문서와 향후 실행 지침을 남기는 범위다. 이 문서 작성 자체가 P06~P09 실행이나 사이트 새 버전 배포를 의미하지 않는다.
