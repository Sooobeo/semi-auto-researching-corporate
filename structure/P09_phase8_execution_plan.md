## 1. 이번에 답할 질문

**같은 자료에서 추출·이전 정보·비교·계산·카드가 근거와 맞게 연결되는가? 사람이 원문만 읽을 때보다 카드로 확인할 때 무엇이 편해지고 무엇을 놓치는가?** 프로그램의 회귀 검사, 새로운 자료의 정확도, 사람 검토의 효용을 다른 결과로 보고한다.

최종 사이트에서는 평가 수치 옆에 실제 문서·항목·family·사람 수와 측정 조건이 보여야 한다. 아직 평가하지 않은 수치는 ‘미평가’로 표시한다. 좋은 데모만으로 전체 정확도나 수익률 개선을 주장하지 않는다.

## 2. 출발점과 독립 평가의 조건

작성 시점의 개발 자료는 Microsoft 1개 기업, release/family 2개, 숫자 33개와 관계 6개다. 두 family는 같은 노출 그룹이다. 기존 P05는 개발 baseline이며 사람 gold·독립 test는 0개다. P06~P08 실행 이후에는 최신 manifest·검토 이력·사이트 버전으로 상태를 다시 확인한다.

| 평가 범위 | 현재/개발 자료에서 수행 | 별도 필요한 조건 |
| --- | --- | --- |
| 파일·schema·ID·근거·수식·재현·실패 처리 | 가능 | 실제 구현과 고정 입력 |
| 기존 agent 참조와 회귀 일치 | 가능, development 결과로만 보고 | 참조 노출 이력·같은 단위 비교 |
| 실제 실행시간·호출 수·관측 비용 | 측정한 값만 보고 | 실제 로그·환경·측정 분모 |
| 독립 추출/관계/검색/change 정확도 | 현재 불가 | 새 평가 manifest·사람 정답·노출/권리 감사 |
| 중요 사건 recall·순위 효용 | 현재 불가 | 사건 universe·중요성 정답·고정 정책·독립 test |
| 원문/카드 사용성 비교 | 실제 참여 시 가능 | 2인 실제 세션·새 과업/노출·순서/측정 protocol |
| 참여자별 학습·분석 수행 | 실제 작업 증거에 한해 가능 | 작성/수정/검토·agent 열람 이력 |

예약 FY2026 Q1 자료는 metadata 확인만으로 독립 test 자격을 갖지 않는다. 새 평가에 쓰려면 본문을 열기 전에 평가 목적·정답 작성 절차·family/관련 노출·권리·개발 제외 규칙을 고정한다. 평가용으로 개봉한 뒤 규칙을 고쳤다면 해당 데이터의 노출 상태를 갱신하고 같은 test에서 재선택한 모델을 독립 결과로 보고하지 않는다.

사람 정답을 agent 판단으로 대체하지 않는다. 사람 주석 부재 때문에 개발 검증을 중단하지 않되 정식 평가 상태는 `not_evaluated` 또는 `blocked_missing_data`로 남긴다.

## 3. 결과를 보기 전에 고정할 protocol

`evaluation_protocol.md`에 다음을 먼저 적는다.

- 평가 질문·주요/보조 지표, 후보/claim/relation/event/family/query/card의 집계 단위.
- 입력 universe·접근 실패 포함 여부·발표 cutoff·검색 모드·권리와 corpus coverage.
- gold 작성/조정 방식·조정 전 독립 기록·노출/분할 정책.
- 실행 비교군과 미구현/미실행 군, 고정 코드/registry/schema/정책/모델/사이트 버전.
- 검토 예산·동률·positive 0·정답 없음·분모 0·실패·중단·결측 처리.
- 사람 과업·정답 접근 조건·영어 이해·순서·연습 제외·idle 규칙.
- dev 근거로 선택한 운영점·허용 오류/검토량/비용 기준과 선택 시각.

독립 dev가 없으면 목표 recall·확률 threshold를 임의 숫자로 채우지 않는다. 허용 오류와 test 성과를 혼동하지 않고 ‘목표 선택 미완료’를 기록한다. 프로토콜 변경은 새 버전으로 남기고 test를 본 뒤의 변경을 표시한다.

## 4. 실제 구현에 맞춘 비교군

| 군 | 비교 내용 | 초기 계획 |
| --- | --- | --- |
| S0 | 같은 허용 원문/최소 근거의 시간순 목록 | 기본 비교 경로 |
| S1 | P06 규칙 기반 검토 사유/시간순 목록 | 학습 모델과 구별해 구현 상태 확인 |
| S3 | P05/P07/P06/P08 통합 카드 | 같은 입력·cutoff·검토 예산으로 비교 |
| S2 | 전통 ML 중요성/분류 모델 | 독립 train/dev·사람 정답이 없으면 미실행 |
| S4/S5 | 선택적 LLM/전체 LLM | 원문 AI/외부 전송 권리·예산·고정 설정 없으면 미실행 |

군마다 제공 기능이 다르므로 기능별 정확도와 전체 검토 효용을 분리한다. S0에 extraction 기능이 없다고 추출 정확도를 0점으로 넣지 않는다. 한국어 템플릿/요약을 제공하는 조건과 원문 접근 범위를 명시한다.

ablation은 실제 구현한 요소 중 사전 선정한 소수만 수행한다. 예를 들어 exact/희소 검색, change 표시 유무, 사유별/시간순 보기를 같은 입력에서 비교한다. safety 검사 제거 실험은 별도 synthetic 경로에서만 수행하며 불검증 결과를 정상 사이트에 게시하지 않는다. 미구현 hybrid·LLM·학습 모델의 효과를 추정해 채우지 않는다.

## 5. 정확한 분모와 미평가 표시

| 결과 | 분모/필수 조건 | 현재 데이터에서 주의할 점 |
| --- | --- | --- |
| 회귀 필드/묶음 일치 | 동일 참조로 평가한 필드/묶음 | 새 자료의 정확도가 아님 |
| 독립 숫자/관계 정확도 | 사람 정답이 있는 평가 항목 | 39개 후보를 39개 독립 사건으로 세지 않음 |
| retrieval Recall@k | qrels가 있는 query·정답 단위와 평균 방식 고정 | 자동 후보를 qrels로 승격하지 않음 |
| change/계산 검증 | 평가 가능한 변화/공식 실행과 실제 정답 | 검색 오류·호환성·산술·해석을 별도 집계 |
| important recall | universe의 중요 사건, 필터/수집/단계 누락 포함 | 중요성 정답 없으면 null/NA |
| 검토율·수정률 | 실제 검토한 고유 사건/카드/필드 등 명시 | 기준 단위를 섞지 않음 |
| 검토시간 | 실제 완료/중단 세션과 idle 정책 | 미측정·기억 효과·사전 노출 공개 |
| 비용/1000문서 | 관측 비용 ÷ 실제 입력 문서 수 ×1000 | 39개 후보를 문서 분모로 사용하지 않음 |

분모 0은 null/NA와 사유를 기록하고 제외 수를 공개한다. empty qrels와 true no-answer는 다르다. 사유가 복수인 경우 사유 합계와 고유 실패 항목 수를 구별한다. package check 통과율·synthetic pass 수를 NLP 정확도나 사람 판단 일치도로 표시하지 않는다.

현재 2개 family·같은 노출 그룹의 development 결과로 일반화 신뢰구간을 만들지 않는다. 독립 family가 충분히 확보된 경우에만 그룹 의존성과 paired 설계를 고려한 분석 방법을 사전 선정한다. 미측정 CI/p-value를 추정 값으로 채우지 않는다.

## 6. 2인 사용성·개인 수행 평가

실제 참여 인원은 사용자와 팀원, 최대 2명이다. 원래 설계의 A/B/C는 기능 역할이며 추가 시험자가 있다는 뜻이 아니다. 두 사람의 소표본 결과는 팀 내부 사용성으로 보고한다.

원문만/카드 조건은 난이도·유형이 비슷한 서로 다른 사례 묶음을 사용하고 순서를 교차 배정한다. 같은 사람이 이미 본 사건을 반복한 결과는 practice 또는 노출된 비교로 표시한다. 두 사람이 결과를 먼저 논의한 뒤의 판단은 조정 전 독립 판단으로 기록하지 않는다.

과업은 주장/관계 근거 찾기, 기간/scope 확인, 이전과 비교 가능한지 설명하기, 추가 확인 질문 고르기다. 시작/완료·근거 열기·수정·중단·idle와 누락을 기록한다. 사람이 참여하지 않았다면 UI 자동 점검을 검토시간·사용성 결과로 바꾸지 않는다. 게시 snapshot에서 측정한 세션은 배포 버전과 데이터 hash를 고정한다.

`learning_cases.jsonl`에는 각자가 실제 수행한 ontology/NLP/business/financial 영역, 원본 작업, 오류·수정, 설명·대안, agent 출력 열람, 검토 이력을 연결한다. 금융 적용 담당만 실제 수작업 계산/대사·가정/메모를 설명하며 모든 팀원에게 금융 산출물을 요구하지 않는다. agent 초안을 읽었다는 사실만으로 개인 이해나 독립 gold를 인정하지 않는다.

## 7. 비용·속도·오류와 재현

실제 환경, 입력 문서/후보 수, cold start/모델 로드·인덱스 생성·warm 처리, API 대기/재시도·캐시 재사용을 분리한다. 외부 호출이 0인 로컬 run에서도 하드웨어·시간과 측정 여부를 남긴다. 전체 비용 미측정을 ‘0원’으로 표시하지 않는다. 유료 호출이 있으면 실제 사용량·통화·단가 확인일을 기록하고 환산은 관측 비용과 구별한다.

실패 사례는 수집·추출·mapping·시점·검색·호환·계산·검토 사유·화면·피드백으로 분류한다. 중요한 누락과 비교 불가·입력 부족을 성능에서 조용히 제외하지 않는다. 사례 선정 기준·전체 오류 수·수정 전후·새 평가 필요성을 남긴다.

재현 묶음은 입력/설정/환경/코드/정책/출력 hash, 실제 CLI·table 생성 방법, 제한 원문 제외 목록을 포함한다. 같은 agent/작성자의 재실행과 팀원의 실제 재실행을 구분한다. private 본문·credential이 있어야만 가능한 재현 경로는 해당 의존성과 접근 제한을 설명하고 원문을 공개 묶음에 복제하지 않는다.

## 9. 산출물·CLI·검증

새 코드는 `scripts/p09_*.py`, 결과는 `artifacts/us_equity/p8/runs/<run_id>/`에 저장한다. CLI 제안은 `p09_run_evaluation.py`(고정 protocol·manifest·비교군·출력), `p09_build_report.py`(실제 결과로 표 생성), `p09_verify_package.py`다. 아직 구현되지 않았으므로 실행된 명령으로 기록하지 않는다.

검증할 반례:

- 오염된 family·연습 사건·feedback 사용이 independent test로 잘못 표시되는 것을 차단한다.
- positive 0·qrels 없음·빈 세션·분모 0에서 거짓 0%/100%를 만들지 않는다.
- stage 실패/필터 탈락이 end-to-end 분모에서 사라지지 않는다.
- 미실행 LLM/ML 군·사람 세션·비용은 점수/0원 대신 미실행·미측정이다.
- 관계 일치·재무 영향 해석·수식 계산·사람 일치도를 하나의 정확도로 합산하지 않는다.
- 관측 비용과 1000문서 환산, 실제 문서와 후보, 독립 family와 공유 근거를 구별한다.
- 사이트의 수치·분모·비교군·한계가 동결 결과파일과 같고 제한 원문/credential이 없다.
- 보고서의 모든 수치/표가 실제 출력으로 재생성되며 좋은 데모만 골라 전체 성능으로 표현하지 않는다.

기존 P04/P05 package 보존과 후속 run의 의미 재현을 확인한다. 이미 적절한 검증을 통과한 뒤에는 새로운 실패/변경이 없는 한 불필요하게 전체 실험을 반복하지 않는다.

## 10. 사이트와 최종 결론

‘검증·평가’ 화면에 실제 실행한 비교군, development/독립 평가 구별, 문서/후보/family/사람 수, 시간·비용·오류·미실행을 보여준다. 점수만 있는 그래프보다 ‘어떤 자료와 조건에서 측정했는지’를 먼저 설명한다. 실패 사례와 비교/계산 불가 이유도 조회할 수 있어야 한다.

[사이트 업데이트 계약](SITE_PHASE_UPDATE_CONTRACT.md)에 따라 같은 사이트를 게시하고 run/결과 hash·버전·배포 상태를 남긴다. 연구/학습 작업을 수행하지 않았다는 이유로 가짜 결과 화면을 채우지 않는다.

**개발 검증 종료:** 실제 비교 가능한 구현·회귀·계산·재현·비용/측정 상태·오류 보고와 사이트 반영을 완료했다. **정식 프로젝트 평가 종료:** 독립 평가와 실제 사람 과업 등 사전 protocol의 필수 항목이 수행됐을 때만 인정한다. 목표 미달은 평가 결과이고, 필수 평가 미실행은 평가 미완료다.

최종 브리핑은 ‘현재 무엇을 직접 사용할 수 있는지 → 실제 검증 범위 → 도움이 됐거나 실패한 사례 → 남은 조건 → 같은 사이트에서 볼 결과’ 순서로 작성한다. 수익률 개선·전체 미국 기업 정확도·2인 결과의 일반화는 결론에 추가하지 않는다.
