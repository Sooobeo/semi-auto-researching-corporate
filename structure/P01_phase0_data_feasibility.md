## 1. 이 단계에서 답할 질문

소수의 미국 관심 기업에서 영문 공시·IR·공식 발표를 재현 가능하게 확보하고, 지표·사건·필요한 사업 관계를 원문 위치까지 추적할 수 있는가? 같은 자료로 기존 상태와 새 정보의 차이를 검토하는 배치·로컬 MVP를 만들 수 있는가?

- **책임 역할:** C 기준·통합, A/B 기업·자료 조사 역할의 임시 표기. 실명·기업 배정은 미정이며 A/B를 고정된 두 기업 또는 팀 인원수로 해석하지 않는다.
- **착수 조건:** 미국 기업 후보와 분석 질문, 로컬 저장소 접근. 최초 범위를 합의한 뒤 이용조건 확인과 소표본 시험을 수행한다.
- **범위:** 미국 관심 기업 소수의 영문 원자료에서 시작한다. 기업 목록·섹터·회계기간·최초 문서 수·확장량은 미정이다. 검토 카드의 설명은 한국어로 작성할 수 있으나 근거는 영문 원문에 연결한다. 기사 문체 비교와 자동 기사 생성은 필수 범위가 아니다.
- **연결 에픽:** [KAN-4](https://qyurimoon.atlassian.net/browse/KAN-4)는 이전 기획의 연결 이력입니다. 외부 이슈가 미국 방향으로 갱신되었다는 뜻은 아니며 실제 담당·기한은 팀과 정합니다.

## 3. 상세 설계와 판단 규칙

### 기업과 문서 선정

기업 A/B는 P01-T01에서 선정할 미국 기업의 자리표시자다. 전사·사업부·제품/서비스·연결 범위를 먼저 구분한다. 관계 분석이 변화 질문에 필요하면 공개된 고객·경쟁·공급·산업 관계를 표본 선정에 포함하되 관계 존재와 실적 영향 해석을 나눈다. 여러 섹터의 전체 관계망 구축은 초기 완료 조건이 아니다.

SEC/EDGAR와 발행사 IR·공식 발표를 **후보 출처**로 검토한다. 기업에 적용되는 공시 유형·제공 형식·이용조건·자동 접근·조회 가능 기간은 새로 확인한다. 공개 페이지나 API의 존재가 원문 저장·AI 이용·재배포 허용을 의미하지 않는다. 소표본 수는 팀의 가용시간과 시험 결과로 정하며 전 기간 접근 가능성을 가정하지 않는다.

회사별 실제 회계연도·분기 시작/종료일과 달력 분기를 따로 적는다. 발표일은 대상 회계기간이 아니며 52/53주 회계연도 등 길이가 다른 기간을 동일 분기로 간주하지 않는다. 뉴스가 필요하면 공식 발표와 언론사 후보를 구분하고 검색 서비스의 시각과 원 게시 시각을 나눈다. 공시·IR 접근률, 기사 URL 수, 고유 기사 수, 기사–사건 링크 수, 발표 family 수의 분모를 따로 유지한다.

### 수집 성공과 본문 추출 성공

화면 열림, 파일 저장, 본문 추출, 표 의미 보존은 서로 다른 열이다. HTTP 200이나 파일 존재만으로 성공 처리하지 않는다. HTML 오류 페이지가 PDF 이름으로 저장되는 경우 MIME·파일 시그니처·페이지 수를 점검한다. 수동 복사 성공을 자동 추출 성공에 포함하지 않는다.

### 문서 ID·버전

문서는 stable doc_id, 다운로드본은 revision_id로 분리한다. 같은 파일 hash는 재수집 로그만 추가한다. 정정 자료는 원문을 덮어쓰지 않고 supersedes_doc_id와 공개시점을 기록한다. 한국어·영어 번역본은 개별 문서이되 같은 발표 그룹을 연결한다. exact duplicate와 같은 사건의 후속 발표는 다르다.

### 최소 저장 체계

원문 보관이 허용되면 `artifacts/us_equity/p0/raw/` 등 새 권리별 위치에 보관하고 manifest에서 연결한다. 먼저 `.gitignore`의 raw/본문 제외 규칙을 확인한다. 제한된 원문은 공유 폴더나 Git에 복제하지 않고 URL·hash·허용된 근거·권한 조건을 남긴다. 키·토큰은 환경변수로 받고 로그·manifest·답변에 노출하지 않는다. 외부 LLM 입력과 학습은 각각 허락 범위를 확인한다.

출처별 약관/계약 근거·확인일·인증·자동 접근·저장·내부 분석·AI 입력/학습·외부 전송·공유·재배포 가능 범위를 따로 기록한다. 불명확하면 `unresolved`와 이유를 남기고 해당 원문의 대량 저장·AI 분석을 보류한다. 허용된 다른 경로의 시험은 계속한다. 언론사 접근은 redirect 최종 도메인의 robots·조건까지 확인하고 호스트 간격·429·`Retry-After`를 지킨다. 403·유료벽·차단·명시적 금지는 우회하지 않는다. 기존 국내 크롤러의 최초 URL robots 검사와 한국기업 표본 고정 검증기를 미국 자료 검증기로 그대로 사용하지 않는다.

### 품질 지표의 분모

접근률=실제 본문을 읽은 고유 문서/접근을 시도한 고유 문서. 자동 추출률=지정 파서가 usable text를 만든 문서/자동 추출 시도 문서. 중복률=중복 판정 다운로드 건/전체 다운로드 건이며 고유 문서 접근률과 분모를 섞지 않는다. 시각 정확도는 정확 시각/날짜만/미상으로 분포를 보고한다. 실패 원인은 권한·파일손상·동적 페이지·OCR 필요·원문 누락·도구 제한으로 분리한다.

### 두 목표를 지원하는 자료 선정

[공통 목표·리서치 적용 흐름](GOALS_AND_RESEARCH_WORKFLOW.md)을 기준으로 사업 관계 변화 표본과 재무 적용 후보를 함께 확인한다. 개인 적용 후보에는 해당 기업의 재무제표·주석·경영진 설명·실적 발표·필요시 GAAP/non-GAAP 조정표가 실제 접근 가능한지 coverage_matrix로 기록한다. 재무상태·손익·현금흐름과 자본 변동의 연결은 선정 질문에 필요한 범위에서 확인하고, 특정 공시 형식을 모든 기업에 적용하지 않는다. 사업 관계만 확인 가능한 사건도 공통 표본으로 유지한다.

최초 재무 개념·사례는 자료 접근성과 추가 작업량을 보고 담당·검토자와 정한다. 재무 자료가 없다는 이유로 비정량 사업 사건을 제외하지 않으며, 공통 개발과 개인 분석 적용의 분담을 scope에 기록한다.

## 5. 필수 검증 시나리오

- [ ] 동일 파일 재수집 시 doc_id가 늘지 않는다.
- [ ] 회계분기·달력분기·누적·연간 열과 기간 길이가 다른 표를 자동 QoQ 비교 대상으로 넘기지 않는다.
- [ ] 공식 페이지 열기 실패는 기업 자료 부재로 기록하지 않는다.
- [ ] 날짜만 있는 발표는 임의로 00:00의 정확 시각이라고 표시하지 않고 DST/시간대 미확인은 미확인으로 둔다.
- [ ] 관계가 있다는 원문을 매출·이익 영향의 확정 근거로 쓰지 않는다.
- [ ] 기존 한국기업 자료·결과나 한국기업 고정 검증 통과를 미국 데이터 검증으로 집계하지 않는다.

## 6. 단계 종료와 다음 단계 전달

**종료 기준:** 고유 문서 목록·원문 위치·실패 및 이용조건이 모두 연결되고 다른 팀원이 실제 문서와 숫자표를 재확인했다. 목표 성공률 수치는 파일럿 결과를 보고 결정 기록에 남기며 달성한 것처럼 미리 기입하지 않는다.

**인계:** P1/P2에 자료와 예외를 전달한다. 품질 불량 형식은 P4 학습에 넣기 전에 보완 또는 제외 근거를 남긴다.

결과 기록에는 완료 작업 ID, 산출물 경로·버전·hash, 실제 건수, 검증 결과, 검토 역할, 남은 문제와 후속 작업을 남깁니다. 미실행 검증을 통과로 표시하지 않습니다. 성능 목표·예산·표본 수 변경은 [결정 기록](DECISIONS.md)에 남깁니다.

## 7. 이 단계의 레퍼런스

- **DIR01 · [미국 기업 방향성 제안](../docs/project_direction/us_equity_research_proposal.md)** — 유지할 질문·검토 카드·배치/로컬 MVP, 미국 소수 기업과 필요한 사업 관계 확장. 개인 제안이며 세부 수치·역할·일정은 팀 합의 전이다. 2026-10-05 사용자 수정에 따라 한국기업 자료·결과는 활성 범위에서 폐기한다.
- **D06 · [SEC EDGAR API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)** — 미국 기업 자료의 후보 경로. 이번 방향 개정에서 실제 조회·전 기간 접근·저장/AI 이용권을 검증하지 않았다.
- **선정 기업의 공식 IR·발표** — 기업을 정한 뒤 상세 URL·자료 유형·회계기간·이용조건을 확인하고 source_registry에 등록한다. 특정 기업이나 자료 제공량을 선결하지 않는다.
- **O03 · [W3C PROV-O](https://www.w3.org/TR/prov-o/)** — 원문→추출→수정→계산의 추적 관계 참고. 실제 구현·적용 검증은 새 자료로 수행한다.

N01/N02와 기존 한국기업 사례는 이전 기획 이력이며 새 미국 표본의 입력·검증 결과가 아니다. 실제 출처를 사용한 뒤 읽은 절·페이지·버전·확인일·실행일을 기록하고, 후보와 검증된 경로를 구분한다.
