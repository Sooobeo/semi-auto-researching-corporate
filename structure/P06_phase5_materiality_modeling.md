## 1. 이 단계에서 답할 질문

어떤 중요성 표현이 사람 간 일관성과 검토 효용을 함께 만족하며, 제한된 검토량 안에서 중요한 사건을 얼마나 보존하는가?

- **책임 역할:** C 연구·평가, B 모델·시간 분할, A 도메인·오류 해석
- **착수 조건:** P3 독립 assessment/gold/split과 P4 예측. P6 변화 특성이 아직 없으면 사용하지 않는 baseline부터 만들고 후속 ablation을 계획.
- **범위:** 표현 후보 비교, 간단 분류·순위 baseline, 시간·기업 검증, 보정·abstention. 사후 주가를 사전 중요성의 유일한 gold로 대체하지 않는다.
- **연결 에픽:** [KAN-9](https://qyurimoon.atlassian.net/browse/KAN-9). 실명·기한은 팀이 배정하며 여기서는 역할 기준으로 작성합니다.

## 3. 상세 설계와 판단 규칙

### 비교할 표현

1) 이진 검토 필요, 2) 순서형 무시/모니터링/모델검토/가정재검토 후보, 3) 가정 영향·리스크·긴급성·근거 충분성 같은 다차원, 4) 다중 label, 5) 필요시 pairwise 우선순위. 이는 확정 라벨이 아니라 P1/P3의 질문 결과로 비교할 후보다. 하나의 축으로 응답이 잘 정렬되지 않으면 억지 합산 대신 분리된 질문과 검토 근거를 제시한다.

### 작은 표본에서의 연구 전략

100~300건에서는 복잡한 잠재요인·다수 모델 탐색을 확정 연구로 주장하기 어렵다. 빈도·혼동·축 간 연관과 사람 간 일치도부터 보고, 충분한 표본이 확보된 경우에만 요인·군집·계층모형을 탐색 분석으로 수행한다. 평가 범주에 positive가 없으면 metric을 NA로 보고한다. 임의로 양성을 복제해 test 분포를 바꾸지 않는다.

### 두 종류의 실험

oracle input 실험은 gold 사실·비교 상태를 사용해 중요성 표현 자체를 본다. end-to-end 실험은 P4/P6 예측을 사용해 실제 오류 영향을 본다. 두 결과를 명확히 분리한다. classifier·ordinal model·tree/ranker 중 사전 계획된 소수 후보를 비교하며 입력 규모에 맞는 단순 모델을 기본으로 둔다.

### feature의 시간 적합성

feature_registry에 source field, 사용 가능 시각, 변환식, train-fit 여부, 누수 위험을 적는다. 공개 당시 없는 차기 실적·정정·수익률·평가자 의견은 feature에서 배제한다. ‘얼마나 바뀌었나’ 특성은 P6의 이전 공개 상태와 호환성 검사 결과에서만 가져온다. novelty를 계산할 prior-state가 없으면 0이 아니라 missing indicator를 둔다.

### 시장 반응 보조 분석

KRX 가격·거래일·수정주가 조건을 확보한 경우에만 별도 outcome 분석을 한다. 추정창·사건창·장중/장후 발표 처리·비거래일·중복 사건·동시 실적발표를 사전에 정한다. 예시 창은 [-120,-21], 사건창 [0,1] 또는 [-1,1]이며 확정값이 아니다. AR=실제 수익률-정상수익률, CAR=사건창 AR 합으로 명시하되 정상모형·벤치마크·추정 오차를 함께 보고한다. 공통 산업 충격·같은 날 복수 사건으로 인해 인과적 효과라고 단정하지 않는다. [R09](REFERENCES.md)는 실제 적용 전 원문 정독이 필요하다.

### 순위·보정·효용

query group은 같은 평가일/검토 세션의 후보 사건이다. Recall@k는 전체 gold 중요 사건 중 상위 k에 포함된 비율이고 candidate 단계에서 누락된 사건도 end-to-end FN이다. NDCG gain 정의를 사전 고정한다. AP와 사다리꼴 PR-AUC를 구별한다. confidence 보정은 별도 dev/calibration에서 하며 표본이 적으면 reliability plot·표본 수를 함께 보여준다.

**종료 기준:** 표현·모델·운영점의 선택 근거, 일치도·시간 평가·한계가 기록됐다. 사후 주가 예측 성공을 리서치 효용의 유일한 증거로 삼지 않는다.

**인계:** P7에는 순위·설명·불확실성 인터페이스, P8에는 고정 표현·운영점·비교군과 미실행 실험 범위를 전달한다.

결과 기록에는 완료 작업 ID, 산출물 경로·버전·hash, 실제 건수, 검증 결과, 검토 역할, 남은 문제와 후속 작업을 남깁니다. 미실행 검증을 통과로 표시하지 않습니다. 성능 목표·예산·표본 수 변경은 [결정 기록](DECISIONS.md)에 남깁니다.
