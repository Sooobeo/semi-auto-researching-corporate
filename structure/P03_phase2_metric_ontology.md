## 1. 이 단계에서 답할 질문

미국 기업의 지표·사건과 필요한 제품/서비스·고객·경쟁·공급·산업 관계를 어떤 개념·규칙으로 표현해야 기존 상태와 새 정보를 일관되게 연결·비교할 수 있는가? 작은 기업 표본에서 만든 기준을 다른 기업·섹터에 적용할 때 무엇을 유지하고 바꿔야 하는가?

- **책임 역할:** A 후보·근거 통합, B 별칭·비교/관계 규칙, C 스키마·적용 검토의 임시 역할안. 실제 분담·기업 배정은 팀과 정한다.
- **착수 조건:** 새 미국 P0 usable corpus, P1 개념/지표/관계 선정 규칙과 사건 필드. 영문 원문 위치·권리·scope·회계기간이 확인된 자료를 사용한다.
- **범위:** 선정 미국 기업의 metric catalog·alias/unit/definition registry와 변화 질문에 필요한 최소 entity/relation catalog, driver 후보, 소표본 적용 점검. 최초 기업·기간·지표/관계 수·적용 표본 수는 미정이다. 전체 시장 관계망·여러 섹터 일반화·정량 예측·관계 화면은 초기 필수 산출물이 아니다.
- **연결 에픽:** [KAN-6](https://qyurimoon.atlassian.net/browse/KAN-6)는 이전 기획의 연결 이력입니다. 외부 이슈가 미국 방향으로 갱신되었다는 뜻은 아니며 실제 담당·기한은 팀과 정합니다.

## 3. 상세 설계와 판단 규칙

### 지표와 사건 상태 구분

매출·출하량·생산능력처럼 측정 대상인 metric과 개발/검증/양산/출하/판매 같은 event status, 기업·제품/서비스 등의 entity, 고객/공급/경쟁/산업 소속 관계를 분리한다. 정성적 ‘수요 개선’은 방향 정보로 보존하고 임의 수치로 치환하지 않는다. 공통 재무·섹터·기업 고유 계층은 실제 정의와 자료를 보고 선정한다. 소수 기업의 등장 빈도만으로 전 산업 공통 개념을 확정하지 않는다.

### 등장 기록과 지표 정의는 다른 표

occurrence는 원문의 특정 표현·위치 한 건이다. catalog는 canonical metric 하나다. 같은 발표의 복제는 독립 사건으로 늘려 세지 않는다. 기업 coverage의 분모는 합의된 실제 선정 기업 수이며 아직 고정되지 않았다. 원문 미공개·찾지 못함·미조사를 구분하고 문서 수·발표 family 수·기업 수·회계기간 수를 따로 집계한다. 관계 주장 수와 고유 관계 수도 따로 보고한다.

### 비교 가능성의 결합 조건

company/scope/product/metric definition/unit/value kind/reference period/consolidation/currency/actual-vs-guidance와 원문 회계 기준을 확인한 뒤 comparable/conditional/not_comparable/unknown을 판정한다. 회계분기·달력분기·누적/연간·기간 길이와 GAAP/non-GAAP 또는 회사 자체 KPI 정의를 섞지 않는다. 생산능력/생산량/출하량은 별도 개념이고 매출 비중은 제품·사업·전사 등 분모가 다르면 별도 지표다.

### 단위와 driver

thousand/million/billion 등 배율은 같은 통화·기간·범위에서 명시적으로 변환하고 원표현을 보존한다. 통화가 다르면 환율 종류·기준일·기간 근거 없이 자동 병합하지 않는다. %와 %p, 전년/전분기/기존계획 대비를 별도로 저장한다. CSV/JSONL 같은 감사 가능한 최소 저장으로 시작하고 [O01/O02](REFERENCES.md)의 개념은 필요성·정의를 검토한다. RDF/그래프 DB·관계 그림 자체가 완료 조건은 아니다.

생산능력×가동률은 생산량의 후보식이다. 수율·재고·제품 mix·단위 조건 없이 출하량과 같다고 둘 수 없다. 출하량×ASP도 같은 제품·기간·단위에 한정한다. driver edge에는 회사 설명/문헌/연구 가정 중 근거 종류와 추가 가정을 표시한다.

### 필요한 사업 관계 선정과 근거

제품/서비스·고객·경쟁·공급·산업 관계 후보마다 변화 분석에서 필요한 질문을 연결한다. 공개 원문이 지지하는 주체 entity_id·관계 종류·대상 entity_id·방향·scope·유효기간·modality·근거·버전을 기록한다. 내부 ID와 확인된 외부 식별자 매핑은 분리하며 ticker나 CIK가 없는 제품·고객 등에도 내부 ID를 사용한다. 같은 기사에 등장했다는 이유만으로 관계를 만들지 않고 경쟁 관계·산업 소속의 판단이 필요한 경우 그 정의·근거·판단 층을 남긴다.

관계 존재에 관한 발표 주장과 실적 영향 해석·계산 가정을 구분한다. 고객 계약 축소가 확인돼도 금액·기간·제품 범위가 미공개라면 매출 감소 규모를 생성하지 않는다. 관계가 바뀌면 과거 기록을 덮어쓰지 않고 유효기간·revision·관계 변경 근거로 추적한다.

### 새 기업·섹터 적용 절차

새 미국 기본 표본을 공동 검토해 기준을 고정한 뒤, 팀과 선정한 추가 기업/섹터의 미사용 표본에 먼저 변경 없이 적용한다. 변경 전 결과를 보존하고 그대로 사용/정의 수정/신규 추가/적용 불가로 나눈다. 최초 범위와 적용 표본의 기업·기간·사건 수는 접근성과 자원에 따라 정한다. 공개되지 않은 KPI·제품 가격·고객 관계는 미공개 또는 미확인으로 남긴다.

**새 적용 점검에서 설계 수정에 사용한 표본은 adaptation이다.** 이를 P3/P8의 untouched 회사 holdout으로 다시 부르지 않는다. 후속 평가용은 별도 미사용 사건·기간으로 예약하고 같은 발표의 원문·전재·번역·정정이 양쪽에 갈라지지 않게 한다. 소표본 적용률은 산업 일반화 성능이 아니다. 적용 기준을 새로 만드는 데 폐기된 한국기업 결과를 재사용하지 않는다.

### 선정 재무 개념과 사업 관계의 공동 정의

[공통 목표·리서치 적용 흐름](GOALS_AND_RESEARCH_WORKFLOW.md)의 재무 후보를 실제 자료로 검토하고 `accounting_concept_catalog.csv`를 기존 metric catalog·entity/relation catalog에 연결한다. 개념의 정의·질문·회계정책·업종 적용범위·반례와 metric의 계산 입력·분모·부호·해석 한계를 사람이 정의한다. 공통 사업 관계·비정량 사건의 선정도 함께 수행한다.

프로젝트 FCF를 채택하면 CFO에서 양의 현금 설비투자 지출을 차감하는 수식과 포함 범위를 등록한다. 회사 발표 FCF·non-GAAP 지표는 회사별 정의를 보존하고 동일 이름만으로 합치지 않는다. 매출채권·재고·매입채무 잔액 변화는 환율·인수 등 비현금 요인을 확인하지 않고 CFO 조정과 동일시하지 않는다. 수식 실행과 대사는 P07에서 수행하며 정의·원문 근거를 먼저 고정한다.

## 4. 실행 작업 — 순서와 완료 기준

아래 번호는 설계서 내부 ID입니다. 예: `P03-T01`은 Phase 2의 첫 작업입니다. `P0-T01`처럼 Phase로 쓴 의존성은 해당 Phase 설계서의 T01을 뜻합니다. 한 작업이 담당자 기준 1~2일보다 커지면 기업·자료형·사건유형 단위로 하위 작업을 나누고 같은 완료 조건을 적용합니다.

### P03-T01 · 지표·사업 관계 후보 범위 고정

- **책임·검토:** A, B 확인
- **선행:** P0-T11,P1-T04
- **입력·참고:** DIR01, 새 미국 P0 문서 목록과 P1 개념/관계 선정 규칙; [공통 목표·리서치 적용](GOALS_AND_RESEARCH_WORKFLOW.md), 선정 사례만 적용

1. 선정 미국 기업·섹터·사업 범위·회계기간·문서종류를 확인한다.
2. 변화 질문에 필요한 최초 지표·관계의 종류와 탐색 규모를 팀과 정한다.
3. 기업별 동일 섹션을 읽을 규칙을 정한다.
4. 조사하지 않은 구간을 표시한다.

5. 사업 관계 후보와 재무 개념 후보의 coverage·분모·작업량을 함께 확인하고 금융 지표만으로 표본을 한정하지 않는다.

- **제출:** `metric_sampling.md`
- **완료 확인:** 전체 대상·독립 사건 분모가 고정됨.
- **실패·미해결 처리:** 실패 입력/원문 위치·시도·원인·다음 확인 역할을 결과 기록에 남깁니다. 누락을 임의 값으로 채워 완료 처리하지 않습니다.

## 5. 필수 검증 시나리오

- [ ] 선정 재무 개념·metric의 정의·분모·부호·회계정책·반례가 원문과 연결되고 회사 조정지표와 프로젝트 계산이 구분된다.
- [ ] 재무 금액이 없는 고객/공급/경쟁 관계도 유효한 정의·변화 질문·근거가 있으면 보존된다.

- [ ] 생산능력과 출하량을 다른 metric_id로 유지한다.
- [ ] 매출 비중의 분모가 다르면 병합하지 않는다.
- [ ] 미공개 CAPA는 0이 아니고 비교 불가 이유가 남는다.
- [ ] 새 정의가 옛 기록에 조용히 소급 적용되지 않는다.
- [ ] 고객/공급 관계의 주장과 실적 영향 해석이 분리되고 미확인 관계는 만들어내지 않는다.
- [ ] 회계분기·달력분기·회사 정의가 다른 동일 명칭 KPI를 자동 병합하지 않는다.

## 6. 단계 종료와 다음 단계 전달

**종료 기준:** 선정 지표·개체·관계에 정의·범위·별칭·시점·근거·버전이 있고, 적용 점검의 유지/수정/추가/불가가 기록됐다. 팀과 정한 표본 범위와 오류·미확인을 보고하고 항목 수만으로 완료하지 않는다. 여러 섹터 일반화나 시스템 정확도는 소표본 합의로 보장되지 않는다.

**인계:** P3에는 새 gold 작성용 지표·관계 registry와 예외, P4에는 매핑/관계 추출 후보사전, P6에는 단위·비교·관계/driver 조건을 전달한다. 한국어 검토 설명은 영문 근거와 구분한다.

결과 기록에는 완료 작업 ID, 산출물 경로·버전·hash, 실제 건수, 검증 결과, 검토 역할, 남은 문제와 후속 작업을 남깁니다. 미실행 검증을 통과로 표시하지 않습니다. 성능 목표·예산·표본 수 변경은 [결정 기록](DECISIONS.md)에 남깁니다.

## 7. 이 단계의 레퍼런스

- **DIR01 · [미국 기업 방향성 제안](../docs/project_direction/us_equity_research_proposal.md)** — 기존 질문에 필요한 최소 제품/고객/경쟁/공급/산업 관계 확장과 미국 소수 기업 시작. 세부 섹터·규모·표본·역할은 팀 논의 전이다.
- **새 P0 선정 기업의 영문 원자료** — 실제 사용한 공시·IR·공식 발표 URL, scope·회계기간·위치·권리 확인 기록을 연결한다. 이전 한국기업 자료·결과는 활성 입력과 검증에서 폐기한다.
- **O01 · [W3C SKOS Reference](https://www.w3.org/TR/skos-reference/)** — 대표명·별칭·상하위·정의·매핑 관계를 설계할 때 참고. 확인 수준: 공식 표준 개요 확인; RDF 도입 자체는 필수 아님.
- **O02 · [EDM Council FIBO](https://spec.edmcouncil.org/fibo/)** — 금융 개념의 정의·관계 참고. 기존 공식 소개 검토이며 선정 섹터의 KPI·사업 관계가 모두 정의돼 있다고 가정하지 않는다.
- **O03 · [W3C PROV-O](https://www.w3.org/TR/prov-o/)** — 원문→추출→수정→계산의 출처·행위·작성 주체 연결. 확인 수준: 공식 표준 확인; v1은 관계형 기록으로 구현 가능.
- **T06 · [Python decimal](https://docs.python.org/3/library/decimal.html)** — 금액·비율 계산의 정밀도와 반올림 규칙. 확인 수준: 공식 문서 확인; 입력 문자열·정밀도·반올림 설정 보존.

N01/N02와 한국기업 사례는 이전 기획 이력이며 새 작업의 권위·입력·검증 결과가 아니다. 문헌·출처를 실제 사용한 뒤 읽은 절·페이지·버전·실행일과 새 개념 선택에 미친 영향을 기록한다. 기존 읽기 상태를 미국 표본 검증 완료로 보고하지 않는다.
