## 1. 이 단계에서 답할 질문

규칙과 가벼운 로컬 모델로 미국 기업 영문 자료의 사건과 필요한 사업 관계를 어디까지 정확하게 추출하며, 어떤 오류에만 더 복잡한 모델이 필요한가?

- **책임 역할:** C 실행·평가 공통, B 모델·사건/관계 추출, A 숫자·지표 규칙·오류 검토의 기능별 제안. 실제 담당자·일정·가용 자원은 별도 배정한다.
- **착수 조건:** 새 미국 P3 gold·split·가이드와 P2 registry 고정. 원문 파서 오류는 추출 모델 오류와 구분하며 기존 한국 자료·라벨·성능을 이어받지 않는다.
- **범위:** 영문 관련성→NER→사건·선정한 제품/서비스·고객·경쟁·공급·산업 관계→지표/개체 매핑의 개별 및 연결 benchmark. 고급 모델을 전부 구현하는 것이 목표는 아니며 단순 baseline 이후 개선 필요성을 검증한다. 기업·섹터·기간·표본·허용 오류 수준·모델은 소규모 실험 후 결정한다.
- **연결 에픽:** [KAN-8](https://qyurimoon.atlassian.net/browse/KAN-8). 실명·기한은 팀이 배정하며 여기서는 역할 기준으로 작성합니다.

## 3. 상세 설계와 판단 규칙

### 모델 비교 순서

M0: 새 영문 사전·Regex·수치/단위/날짜·부정·modality 규칙과 근거가 있는 관계 pattern. M1: 문서/문장 관련성 TF-IDF + Logistic Regression 또는 Linear SVM. M2: 사건/관계 인자 CRF 또는 영문 금융 텍스트에 적합성을 시험한 작은 encoder. M3: 필요할 때만 encoder relation extraction·embedding metric/entity matching. M1 문서 분류와 M2 span extraction은 같은 과업의 점수인 것처럼 직접 비교하지 않는다. 각 stage의 공통 입력·출력과 전체 pipeline 성능을 함께 보고한다. 한국어 검토 문구는 선택적 출력이며 영문 원문 추출 benchmark와 분리한다.

### 모델과 학습 데이터

설치 버전·모델 revision·tokenizer·라이선스·데이터 cutoff를 manifest로 고정한다. [R05](REFERENCES.md)는 영문 금융 후보 연구의 출발점이며 정답기나 사건·관계 과업 성능 보장이 아니다. [R04](REFERENCES.md)의 한국어 benchmark를 기본 모델 선정 근거로 쓰지 않는다. 새 미국 gold 규모와 실제 하드웨어를 확인하고 규칙·동결 encoder·간단 분류부터 평가한다. tokenizer의 기업명·제품명·금액·재무 표현 분절과 원문 span 복원을 영문 표본에서 점검한다. 테스트를 반복 조회하며 규칙을 고치지 않는다. 사전·IDF·alias 확장도 새 미국 train/dev에서만 만들고 테스트 기원 항목을 표시한다.

무료 자료와 보유 컴퓨팅 자원을 우선 시험한다. 실제 문서 수·token 수·메모리·처리시간·재시도·비용을 측정해 가능한 배치 규모를 정하며 무료 대량 처리나 상시 운영을 전제하지 않는다. 예산·모델·운영량의 확정은 실험과 결정 기록을 따른다.

### 입력 보존과 span

document→block→sentence의 영문 원문 위치 매핑을 보존한다. Unicode 정규화·공백 수정 전에 raw_text를 보존하고 Unicode code point offset mapping을 작성해 왕복을 확인한다. 긴 문서의 chunk overlap에서 같은 인자를 중복 이벤트로 만들지 않는다. 표 머리글의 단위·기간·scope는 숫자 셀과 함께 추출한다. 숫자만 맞고 잘못된 행에 연결되면 실패다. 선택적 한국어 검토 문구는 원문 claim/evidence ID와 연결하고 번역 offset을 원문 offset으로 사용하지 않는다.

### 관계 추출과 연결

실제 변화 질문에 필요한 관계만 benchmark에 넣는다. 관계의 양끝 개체·기업/고객/공급자 등의 역할·방향·제품/서비스·scope·유효/적용 시점·부정·modality·조건·화자·근거를 보존한다. 동시 언급·임베딩 유사도만으로 관계를 확정하지 않는다. 관계가 있다는 발표 주장과 매출/시장 영향 해석은 facts와 assessments로 분리하며, 원문이 지지하지 않는 영향이나 수치를 자동 생성하지 않는다.

### 평가 단위

관련성 precision/recall/F1/AP, span exact F1와 relaxed F1(별도), 기업·개체·metric top1/topk, 값·단위·기간 exact match, 사건 tuple 전체 정확도를 구분한다. 관계는 양끝 개체·역할·방향·유형·scope·시점·부정·modality의 필드별 성능과 전체 tuple precision/recall/F1을 따로 낸다. 입력 후보에서 누락된 사건·관계는 최종 pipeline FN에 포함한다. 조건부 추출 성능과 전체 입력 기준 성능을 나란히 제시한다. P3 사람 간 일치도는 시스템 정확도와 별도다. 원문 근거가 없는 예측은 사실 레코드로 통과시키지 않으며 평가할 수 없는 사례의 수와 이유도 보고한다.

### 선택적 LLM 비교

API 호출은 optional backend로 설계한다. disabled 상태에서도 모든 입력에 결과/오류 레코드가 남아야 한다. dev에서 선정한 복합관계·미정 지표·낮은 confidence 유형에만 호출하는 정책을 비교한다. 입력 범위·모델 ID·prompt hash·허용된 응답 참조·token·비용·실패를 기록하고 구조·근거를 검증한다. 실제 호출 전에 출처별 AI 입력·외부 전송·보관 권리와 당시 모델·단가·예산을 확인한다. 권리가 미확정인 본문은 전송하지 않고 미실행 이유를 기록한다. 문서는 특정 미검증 endpoint를 확정하지 않는다.

### 오류에 따른 다음 행동

파서 누락은 P0 보완, scope/단위·개체/역할 정의는 규칙과 registry, 같은 사건·관계 연결은 P1/P6, 모호한 gold는 P3 조정으로 보낸다. 검토 카드의 review_readiness 후보 supported / needs_review / not_comparable과 불확실 이유를 별도로 전달한다. supported는 원문이 기록한 주장을 지지한다는 뜻이며 외부 사실 확인 완료나 보정된 확률을 뜻하지 않는다. 모델 크기 증가가 모든 실패의 기본 대응은 아니다.

### 재무 문맥을 포함한 NLP 검증

[공통 목표·리서치 적용 흐름](GOALS_AND_RESEARCH_WORKFLOW.md)의 선정 재무 개념은 기존 지표·사건·관계 추출에 추가하는 문맥이다. 표의 괄호 음수·현금 지출 부호·단위 scale·기간 머리글·분기/누적·잔액/기간 흐름·GAAP/non-GAAP 조정 위치를 감사한다. 공통 사업 관계·시점·조건·부정 추출과 별도로 오류를 집계하고, 재무 파싱 성공으로 관계 추출 검증을 대체하지 않는다.

수치·정의 mapping은 원문과 등록부로 확인하며 개인 해석·회사 가이던스·프로그램 계산을 actual_reported claim으로 만들지 않는다. 참여자가 직접 찾은 오류·변경한 정의/규칙과 검증 결과를 원본 작업에 남겨 P09 학습 사례에서 참조한다. 기존 회귀 검사나 수식 일치만으로 새 미국 표본의 전체 정확성을 주장하지 않는다.

## 4. 실행 작업 — 순서와 완료 기준

아래 번호는 설계서 내부 ID입니다. 예: `P05-T01`은 Phase 4의 첫 작업입니다. `P0-T01`처럼 Phase로 쓴 의존성은 해당 Phase 설계서의 T01을 뜻합니다. 한 작업이 담당자 기준 1~2일보다 커지면 기업·자료형·사건유형 단위로 하위 작업을 나누고 같은 완료 조건을 적용합니다.

- **선행:** P3-T12
- **입력·참고:** T01,T02,split manifest

## 5. 필수 검증 시나리오

- [ ] 선정 재무 표본의 괄호 음수·현금 지출 부호·분기/누적·잔액/기간 흐름·조정표 위치 오류가 별도로 검증된다.
- [ ] 재무 파싱 성능과 기업·제품·고객/공급 관계의 추출·연결 성능을 각각 보고한다.

- [ ] 문서 머리글의 단위와 다른 행의 숫자를 연결하면 실패 처리한다.
- [ ] 원문 공백 정규화 후에도 evidence span을 복원한다.
- [ ] 같은 문장 복수 회사·지표·고객·공급자가 서로 잘못 연결되거나 관계 방향이 뒤바뀌지 않는다.
- [ ] LLM 미사용·timeout·schema 오류 입력에서도 pipeline 추적이 유지된다.
- [ ] 부인·계획·가능성·조건부 관계를 완료 사실로 바꾸거나 관계에서 실적 영향 수치를 만들어내지 않는다.
- [ ] 한국어 검토 문구가 영문 원문 근거나 독립 평가 표본을 대신하지 않는다.
- [ ] 기존 한국 기업 자료·사전·라벨·성능이 새 미국 benchmark에 혼입되지 않는다.

## 6. 단계 종료와 다음 단계 전달

**종료 기준:** 공통 benchmark에서 최소 규칙 baseline과 관련 과업의 학습 baseline을 비교하고 선택 근거·오류·재현 설정을 남겼다. 성능이 낮으면 범위·데이터·가이드를 보완하며 모델 학습 자체를 성공 결과로 쓰지 않는다.

**인계:** P5에는 사건·관계의 추출 불확실성을 포함한 features, P6에는 근거가 연결된 표준 사건/관계 후보, P7에는 버전 고정 extractor interface와 검토 상태. 미국 표본에서 측정한 범위·정확도·처리량·비용·미해결 오류를 전달하며 다른 기업/섹터의 보장으로 확대하지 않는다.

결과 기록에는 완료 작업 ID, 산출물 경로·버전·hash, 실제 건수, 검증 결과, 검토 역할, 남은 문제와 후속 작업을 남깁니다. 미실행 검증을 통과로 표시하지 않습니다. 성능 목표·예산·표본 수 변경은 [결정 기록](DECISIONS.md)에 남깁니다.

## 7. 이 단계의 레퍼런스

- **DIR01 · [미국 기업 프로젝트 개인 제안](../docs/project_direction/us_equity_research_proposal.md)** — 영문 자료의 사건·필요한 사업 관계와 실제 자원 안의 정확성 검증 방향. 개인 제안이며 모델·표본·성능·예산·역할의 확정 근거는 아니다.
- **R02 · [Zheng et al. (2019), Doc2EDAG](https://aclanthology.org/D19-1032/)** — 문서 단위 사건·분산된 인자·여러 사건의 표현 설계. 이전 기록의 확인 수준: 서지·초록 확인; 중국어 자료 성능을 새 영문 과업의 예상 성능으로 사용하지 않는다.
- **R04 · [Park et al. (2021), KLUE](https://arxiv.org/abs/2105.09680)** — 한국어 NER·RE 평가 설계의 선택적 비교 문헌. 이전 기록의 확인 수준: 서지·초록 확인; 영문 모델의 기본 선택이나 미국 금융 사건 gold가 아니다.
- **R05 · [Yang et al. (2020), FinBERT](https://arxiv.org/abs/2006.08097)** — 금융 도메인 적응의 비교 후보와 한계. 이전 기록의 확인 수준: 서지·초록 확인; 모델의 실제 언어·과업·라이선스와 사건/관계 적합성은 새 표본으로 확인한다.
- **R06 · [Reimers & Gurevych (2019), Sentence-BERT](https://aclanthology.org/D19-1410/)** — 문장 임베딩 후보·유사도 검색의 역할. 확인 수준: 서지·초록 확인; 유사도는 같은 사건의 증거가 아님.
- **T01 · [scikit-learn model evaluation](https://scikit-learn.org/stable/modules/model_evaluation.html)** — 각 metric의 분모·평균 방식·undefined 조건 확인. 확인 수준: 공식 문서 확인; 설치 버전과 문서 버전 맞추기.
- **T02 · [scikit-learn cross validation](https://scikit-learn.org/stable/modules/cross_validation.html)** — 시간 분리·그룹 분리·누수 방지 평가 설계. 확인 수준: 공식 문서 확인; 일반 TimeSeriesSplit만으로 사건 묶음 분리가 보장되지 않음.
- **T03 · [scikit-learn calibration](https://scikit-learn.org/stable/modules/calibration.html)** — 보정 곡선·확률 평가·별도 보정 데이터 운영. 확인 수준: 공식 문서 확인; 낮은 Brier만으로 보정 품질 단정 금지.
- **T04 · [Sentence Transformers STS](https://www.sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html)** — 임베딩·유사도 구현 후보. 이전 기록의 확인 수준: 공식 문서 확인; 영문 금융·기업 관계 적합성은 새 표본에서 자체 평가.
- **T07 · [Pydantic Models](https://pydantic.dev/docs/validation/latest/concepts/models/)** — 입출력 스키마·누락·타입 오류 검증 후보. 확인 수준: 공식 문서 확인; 강제 형변환과 엄격 검증을 구별.

문헌·API를 실제 작업에 사용한 뒤 읽은 절·페이지·버전·실행일을 기록합니다. 확인한 개요와 아직 정독하지 않은 본문을 구별합니다.
