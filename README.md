# 🔎 기업리서치 반자동화 시도하기

**새로운 기업정보에서 달라진 점을 찾아, 사람이 검토할 가치가 있는 사건을 선별하는 Research Triage 프로젝트**

뉴스·공시·IR 자료에서 기업, 지표, 수치, 기간, 사건을 구조화하고 기존 정보와 비교합니다. 검토자는 원문 근거가 연결된 **Review Card**를 통해 무엇이 달라졌고 어떤 가정을 확인해야 하는지 파악할 수 있습니다.

> 연구 기반 데이터사이언스·NLP 프로젝트입니다. 아래 기능과 로드맵은 기획 기준이며, 구현 완료나 성능 달성을 의미하지 않습니다. 최종 모델·데이터 범위·평가 기준은 문헌 조사와 파일럿 실험을 통해 결정합니다.

## 해결하려는 문제

기업 리서치에서는 새 발표가 기존 전망과 가정을 바꾸는지 판단하기 위해 많은 문서를 반복해서 읽고 비교해야 합니다.

- 관련 없는 문서와 홍보성 내용을 걸러내야 합니다.
- 같은 사건을 다루는 중복 기사와 후속·정정 발표를 구분해야 합니다.
- 기업·제품·지표의 표현을 통일하고 수치·단위·기준기간을 확인해야 합니다.
- 직전 가이던스와 비교해 변화의 의미와 연결되는 지표를 파악해야 합니다.

이 프로젝트의 목표는 **중요한 사건을 놓치지 않으면서 검토 문서 수, 검토시간, API 비용을 줄이는 것**입니다. 시스템은 사람의 리서치 판단을 보조하며, 종목 추천이나 자동 매매를 목적으로 하지 않습니다.

## 동작 예시

아래 문장과 카드는 **설명을 위한 가상 예시**입니다.

> “SK하이닉스는 2027년 HBM 생산능력을 기존 계획보다 20% 확대할 예정이다.”

### 1. 비교 가능한 사건으로 구조화

| 필드 | 추출 내용 |
| --- | --- |
| 기업 / 제품 | SK하이닉스 / HBM |
| 사건 유형 | 생산능력 확대 계획 |
| 지표 / 변화량 | 생산능력 / +20% |
| 비교 기준 / 적용 기간 | 기존 계획 / 2027년 |
| 확실성 | 계획 |
| 근거 | 원문 문장과 출처 |

### 2. 기존 정보와 비교하고 검토 카드 제공

```text
[SK하이닉스 / HBM 생산능력]

새 정보       2027년 생산능력을 기존 계획 대비 20% 확대할 계획
비교 대상     직전 회사 가이던스 또는 연구용 baseline
변화 해석     기존 계획의 상향 수정 가능성
연결 지표     생산능력 → 출하량 → 매출 → 영업이익
확인할 가정   증설 시점, 가동률, 실제 출하 전환 여부
근거          원문 문장과 출처
```

정량화할 수 있는 사건은 명시적인 수식과 가정을 적용해 시나리오를 계산합니다. 생산능력 증가율이 그대로 매출 증가율이 된다고 가정하지 않으며, 입력값·단위·수식·모델 버전을 함께 제시합니다.

## 시스템 설계

```text
뉴스·공시·IR 수집
  → 텍스트 정제·문장 분리·중복 탐지
  → 관련 문서·문장 선별
  → 사건 추출·기업 및 지표 표준화
  → 과거 자료와 기존 상태 검색
  → 변화 탐지
  → 중요도 판단·우선순위화 / 정량 시나리오 계산
  → 근거가 연결된 Review Card
  → 사람의 확인·수정 피드백
```

| 모듈 | 설계 방향 |
| --- | --- |
| 데이터 수집 | 출처·URL·발행 및 수집 시각·문서 hash·정정 관계를 함께 기록 |
| 전처리·중복 탐지 | 본문 추출, 숫자·단위·날짜 정규화, 동일 사건의 후속·정정·부인 연결 |
| 관련성 분류 | 키워드 규칙, TF-IDF 기반 분류, 소형 한국어 모델, LLM baseline 비교 |
| 사건 추출 | 주체·사건·지표·수치·기간·확정 여부·원문 근거 추출 |
| 기업·지표 표준화 | 기업 별칭, 지표 정의, 단위 호환성을 이용해 표현 통일 |
| 기존 상태 검색 | 기업·지표·기간 조건 검색과 BM25·의미 검색을 결합 |
| 변화 탐지 | 수치 변화, 가이던스 수정, 반복 보도, 확실성 및 시행시점 변화 비교 |
| 중요도 모델링 | 사람의 평가와 실험에 근거해 점수·등급·다차원 표현 및 순위 모델 비교 |
| 시나리오 계산 | 정량 사건에 대해 base·bull·bear 가정별 결과를 코드로 계산 |
| 검토·피드백 | 단계별 신뢰도와 불확실성을 표시하고 확인·수정 결과를 학습에 활용 |

### 핵심 설계 원칙

- **비교 시점 준수:** 사건 발생 전까지 알려진 기업 상태를 복원해 신규 정보와 비교합니다.
- **근거 추적:** 추출 결과와 변화 판단을 원문 문장 및 출처에 연결합니다.
- **재현 가능한 계산:** 수치 계산은 Python·SQL 등의 명시적인 코드로 수행합니다.
- **선택적 LLM 사용:** 신뢰도가 낮은 복합 문장, 모호한 지표, 어려운 정성적 관계 등에 제한적으로 사용합니다. 결과에는 구조·근거 구간·단위 검증을 적용합니다.
- **사람의 검토:** 불확실성과 확인할 가정을 드러내고, 사용자의 수정과 추가조사 결과를 반영합니다.

## 주요 연구 질문

| 질문 | 검토할 내용 |
| --- | --- |
| RQ1. 사건을 어떤 단위로 표현할 것인가? | 기사·문장·개별 사건·중복 사건 묶음의 차이, 정정 및 후속 발표의 관계 |
| RQ2. 산업별 핵심 지표를 어떻게 선정할 것인가? | 반복성, 기업별 적용 범위, 매출·이익 예측과의 연결, 정의의 안정성 |
| RQ3. 중요도(Materiality)를 어떻게 표현할 것인가? | 단일 점수·순서형 등급·다차원·복수 라벨의 적합성과 평가자 간 일관성 |
| RQ4. 저비용 NLP로 어디까지 처리할 수 있는가? | 규칙·로컬 모델의 성능과 오류 유형, LLM 추가 사용의 효과 |
| RQ5. 실제 검토 업무가 줄어드는가? | 중요 사건 탐지율을 유지하면서 문서 수·확인시간·수정 횟수를 줄이는지 |

여기서 **Materiality**는 새 정보가 기존 가정, 모델, 투자논리, 리스크 판단 또는 검토 행동을 바꿀 잠재적 정도를 뜻합니다. 차원과 임계값은 연구를 통해 결정합니다.

### 기술 후보

아래는 비교·검토 대상이며 확정된 의존성이 아닙니다.

- **처리·계산:** Python, SQL, Pandas, NumPy
- **분류·정보 추출:** Regex, 사전, TF-IDF, Logistic Regression, SVM, CRF, KLUE-RoBERTa·KoELECTRA 계열
- **검색·표준화:** BM25, Sentence Embedding, fuzzy matching, bi-encoder, cross-encoder
- **중요도 모델링:** Ordinal Regression, Random Forest, XGBoost·LightGBM, Learning-to-Rank, Multi-label Classification
- **프로토타입:** Streamlit 또는 웹 기반 UI

## 평가 계획

시간순 뉴스, 키워드 필터, 전통 머신러닝, 로컬 NLP, 선택적 LLM, 전체 LLM 처리 방식을 비교합니다. 시간순 분리와 기업별 holdout을 통해 새로운 시기·기업에서도 성능이 유지되는지 검증합니다.

| 평가 영역 | 주요 지표 |
| --- | --- |
| 관련성 분류 | Precision, Recall, F1, PR-AUC |
| 정보 추출 | Entity·Relation F1, 숫자·단위·기간 Exact Match |
| 지표 표준화 | Top-1·Top-k Accuracy, 단위 불일치율 |
| 중요도·순위 | Recall@k, NDCG@k, PR-AUC, 신뢰도 보정 |
| 검토 효용 | 중요 사건 recall, 검토 문서 수, 평균 검토시간, 수정률 |
| 비용·속도 | 1,000문서당 LLM 호출 수·API 비용·처리시간 |
| 신뢰성 | 근거 연결률, 재현 가능한 계산 비율, 단계별 신뢰도 보정 |

구체적인 목표 수치는 파일럿 이후 결정합니다. **핵심 성공 기준은 중요한 사건의 recall을 유지하면서 사람의 검토 부담을 줄이는 것**입니다.
