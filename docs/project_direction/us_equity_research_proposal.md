# 미국 기업을 대상으로 한 온톨로지·NLP 프로젝트 — 개인 방향성 제안

수정일: **2026-10-04**. 기존 팀 기획을 바탕으로 대상과 개념 체계의 확장을 제안하는 팀 논의용 문서입니다. 팀 전체의 변경 합의를 의미하지 않으며, 세부 범위·목표·역할은 팀장님 및 팀원들과 논의해 정합니다.

**기존의 “새 정보가 기존 상태를 어떻게 바꾸는가”라는 질문을 유지하면서, 미국 관심 기업을 대상으로 온톨로지와 자연어처리를 직접 다루고 시장 흐름을 분석하는 경험을 얻고 싶습니다.**

## 1. 기존 기획에서 유지할 것과 변경을 제안할 것

변경을 제안하는 항목은 **대상과 개념 체계 두 가지**입니다. 핵심 질문, 사용자 결과물, 초기 운영 방식은 기존 기획을 따릅니다.

| 항목 | 기존 기획 | 이번 개인 제안 | 구분 |
| --- | --- | --- | --- |
| 대상 | 한국 반도체 기업 | 미국 관심 기업 소수부터 시작하고, 이후 여러 섹터로 확장 가능성 검토 | 변경 제안 |
| 질문 | 새 정보가 기존 상태를 어떻게 바꾸는가 | 동일하게 유지 | 유지 |
| 개념 체계 | 지표·사건·비교 조건 중심 | 기존 체계에 제품·고객·경쟁·공급·산업 관계를 추가하는 방향 검토 | 확장 제안 |
| 사용자 결과 | 변화·근거가 있는 검토 카드 | 동일하게 유지 | 유지 |
| 운영 | 배치 처리·로컬 검토 MVP | 동일하게 유지 | 유지 |

새로운 기업 발굴이나 시장 관계 탐색은 개인적으로 관심 있는 활용 방향입니다. 이를 별도 화면이나 필수 기능으로 확정하기보다, 기존의 변화 탐지와 검토 카드가 제공하는 정보를 활용하는 것으로 시작하고 싶습니다.

## 2. 개인적으로 얻고 싶은 것

우선순위는 다음과 같습니다.

1. **온톨로지를 직접 설계·구축·검증해 보는 경험:** 기업 정보를 어떤 개념과 관계로 표현할지 정의하고, 실제 자료에 적용하면서 수정하는 과정을 경험하고 싶습니다.
2. **자연어처리를 실제 기업 자료에 적용하는 경험:** 문장에서 기업·지표·사건·관계·시점 등을 추출하고, 기존 정보와 연결하는 방법을 배우고 싶습니다.
3. **시장 흐름과 기업의 사업 구조를 분석하는 능력:** 새로운 발표가 기존 전망이나 사업 조건을 어떻게 바꾸는지 근거를 따라 이해하고 싶습니다.

궁극적인 동기는 미국주식 투자 판단과 수익률 개선입니다. 다만 이번 프로젝트에서는 **온톨로지·NLP를 다뤄본 경험과 시장 흐름 분석을 더 중요한 직접 목표**로 두고 싶습니다. 수익률 개선을 프로젝트의 보장된 성과나 필수 평가 지표로 삼지는 않습니다.

특정 직무에 맞춘 포트폴리오 형식보다, 실제 데이터를 다루고 분석 과정과 오류·개선 내용을 설명할 수 있는 경험을 얻는 것이 중요합니다. AI agent 활용과 바이브코딩 경험을 구현에 활용하되, 데이터의 의미와 추출 결과를 이해하고 검증하는 과정에도 참여하고 싶습니다.

## 3. 온톨로지 확장이 기존 질문에 어떻게 도움이 되는가?

온톨로지는 정보를 같은 의미와 기준으로 기록하기 위한 **개념·관계·규칙의 체계**로 이해하고 있습니다. 기존 지표·사건·비교 조건에 사업 관계를 추가하면, 변화가 발생한 맥락을 더 구체적으로 설명할 수 있을 것으로 생각합니다.

| 확장할 개념·관계 후보 | 기존 변화 분석에 활용할 질문 |
| --- | --- |
| 제품·서비스 | 새 정보가 어느 제품과 사업의 기존 전망을 바꾸는가? |
| 고객 | 계약·고객 구성의 변화가 기존 매출 의존 구조를 어떻게 바꾸는가? |
| 경쟁 관계 | 새로운 경쟁사 발표가 기존 경쟁 조건을 어떻게 바꾸는가? |
| 공급 관계 | 공급 계약·제약의 변화가 기존 생산·판매 계획에 어떤 영향을 줄 수 있는가? |
| 산업 관계 | 여러 기업의 발표에서 공통된 변화가 관측되는가? |

모든 관계를 처음부터 구축하는 것은 아닙니다. 실제 자료와 분석 질문에 필요한 개념부터 선정하고, 적용 범위와 정의를 팀과 함께 정하고 싶습니다. 관계가 있다는 사실과 실적에 영향을 준다는 해석도 구분해서 기록합니다.

### 가상 적용 예시

다음은 실제 기업의 발표가 아닌 설명용 사례입니다.

```text
기존 정보: 가상기업 A의 주요 제품은 고객 B와의 계약을 바탕으로 판매될 계획이다.
새 정보:   A가 B와의 계약 축소를 발표했다.

구조화: 기업 A / 제품 / 고객 B / 계약 축소 / 적용 시점 / 원문 근거
비교:   기존 계약과 판매 계획에서 무엇이 달라졌는지 확인
검토 카드: 기존·새 정보, 변화 내용, 근거, 영향 판단에 필요한 추가 확인 사항
```

고객·제품 관계는 변화의 맥락을 설명하는 데 사용합니다. 계약 축소만으로 매출 감소 규모를 확정하지 않고, 공개된 수치와 적용 범위가 있는지 확인합니다.

## 4. 결과물과 운영 방식에 대한 이해

프로젝트 결과물은 기존 기획의 **근거가 연결된 검토 카드와 이를 만드는 처리 과정의 프로토타입**을 기준으로 이해하고 있습니다.

```text
자료 수집·정제
  → 지표·사건·필요한 사업 관계 추출 및 표준화
  → 기존 상태와 근거 검색
  → 변화 탐지와 검토 우선순위화
  → 기존·새 정보와 불확실성이 보이는 검토 카드
  → 사람의 확인·수정
```

초기에는 배치 실행과 로컬 검토 MVP를 유지합니다. 웹 화면이나 관계 시각화에는 관심이 있지만, 기업 페이지·테마 화면·자동 갱신 웹사이트를 이번 제안의 필수 산출물로 추가하지 않습니다. 화면 구성과 자동화 수준은 기존 기획 안에서 팀과 논의하고 싶습니다.

온톨로지는 별도의 그래프 그림을 만드는 데서 끝나는 것이 아니라, 정보 추출·연결·비교를 일관되게 수행하는 기준으로 사용하고 싶습니다. 구체적인 저장 방식, 모델, 관계 표현 방법은 자료와 자원을 확인한 뒤 정합니다.

## 5. 정확성에 대한 기대와 교차검증

주어진 컴퓨팅 자원·비용·시간을 고려하면 모든 정보와 관계를 높은 정확도로 자동 처리하기는 어려울 수 있습니다. 그렇더라도 **어떤 범위에서 어느 정도 정확하게 처리할 수 있는지 측정하고, 사용할 수 있는 수준을 팀과 합의하는 것**은 필요하다고 생각합니다.

처음부터 높은 정확도를 전제하거나 낮을 것이라고 단정하기보다, 소규모 실제 자료에 적용한 결과를 확인하고 목표를 정하고 싶습니다.

| 확인 영역 | 사람이 교차검증할 내용 |
| --- | --- |
| 개념·정의 | 같은 표현을 같은 개념으로 볼 수 있는지, 서로 다른 개념을 잘못 합치지 않았는지 |
| 개체·관계 추출 | 기업·제품·고객 등의 대상과 관계가 원문에 맞게 연결됐는지 |
| 상태·시점 | 계획·실적·가능성·부인과 적용 시점을 구분했는지 |
| 기존 정보 비교 | 비교 대상의 지표·범위·기간·단위가 적절한지 |
| 근거 연결 | 연결한 원문이 실제로 해당 주장과 변화 판단을 지지하는지 |

같은 표본을 팀원이 독립적으로 기록하고, 의견이 다른 부분은 원문과 정의를 함께 확인하는 방식으로 시작하고 싶습니다. 사람끼리의 일치도와 시스템의 추출·연결 정확도는 구분하고, 사람이 판단하기 어려운 사례는 불확실한 상태로 남깁니다.

교차검증한 표본의 결과가 전체 데이터의 정확성을 보장하지는 않습니다. 오류 유형과 표본 범위를 함께 기록하고, 기준을 수정하는 데 사용한 자료와 이후 평가 자료도 구분합니다. 사람이 모두 합의했더라도 원문 자체의 오류나 공개되지 않은 관계까지 해결한 것은 아닙니다.

구체적인 목표 수치·검토 표본 수·허용 오류 수준은 팀장님과 논의하겠습니다. 특히 **확실한 정보, 추가 확인이 필요한 정보, 비교하기 어려운 정보**를 검토 카드에서 구분할 수 있는 기준을 정하고 싶습니다.

## 6. 초기 범위와 참여 조건

| 항목 | 개인 선호·가용 조건 |
| --- | --- |
| 시작 범위 | 관심 있는 미국 기업 소수의 자료를 깊게 정리 |
| 확장 방향 | 반도체에 한정하지 않고 여러 섹터에 적용할 수 있는 구조 검토 |
| 자료·질문 선정 | 실제 접근 가능한 자료와 기존 변화 분석 질문을 기준으로 팀과 결정 |
| 기간 | 6개월 이상 참여 가능 |
| 가용시간 | 본인 주당 약 30시간 |
| 예산 | 우선 무료 자료와 보유 컴퓨팅 자원 활용 희망 |
| 역할 | 방향과 작업 범위를 정한 뒤 팀과 분담 |

무료 운영은 선호하는 출발 조건이며, 대량 처리나 상시 운영까지 무료로 가능하다고 전제하지 않습니다. 처리 가능한 문서량·모델·실행 시간은 실제 자원을 확인하고 결정합니다.

현재 저장소의 원문 보존·공통 ID·시점·단위·중복·정정·근거 추적 구조는 유지하는 방향입니다. 한국 기업용 수집·추출 코드 중 공통 부분과 출처별 부분을 검토해 미국 자료에 적용하고 싶습니다. 기존 단계별 계획을 따르되 필요한 대상·관계 확장을 함께 조정합니다.

## 7. 팀장님과 논의하고 싶은 사항

1. 미국 관심 기업을 초기 대상으로 전환하는 것의 적절성과 자료 접근 가능성.
2. 기존 변화 분석에 도움이 되는 제품·고객·경쟁·공급·산업 관계의 선정 범위.
3. 최초 기업·자료·사건 표본과 팀원의 교차검증 방식.
4. 가용 자원 안에서 목표로 할 추출·연결·비교 정확성과 불확실성 표시 기준.
5. 기존 검토 카드·배치 처리·로컬 MVP 안에서 맡을 작업과 역할 분담.

세부 기능·성과 목표·일정·화면 구성은 이 문서에서 확정하지 않고 팀장님과 의논하고 싶습니다.

## 8. 개인 방향성 요약

> 기존의 “새 정보가 기존 상태를 어떻게 바꾸는가”라는 질문과 검토 카드, 배치 처리·로컬 MVP 방향은 유지하고 싶습니다. 대상은 미국 관심 기업 소수로 시작하고, 기존 지표·사건 체계에 제품·고객·경쟁·공급·산업 관계를 추가하는 방향을 제안합니다.
>
> 개인적인 궁극적 동기는 투자 판단과 수익률 개선이지만, 이번 프로젝트에서 더 중요하게 얻고 싶은 것은 온톨로지와 자연어처리를 실제로 다뤄본 경험, 그리고 근거를 바탕으로 시장 흐름을 분석하는 능력입니다.
>
> 정확성에는 한계가 있을 수 있으므로, 팀원이 원문과 개념 정의를 교차검증하고 가용 컴퓨팅 자원·비용·시간 안에서 어느 정도의 정확성을 확보할 수 있는지 확인하고 싶습니다. 구체적인 수준과 세부 목표는 팀과 함께 정하겠습니다.
>
> 6개월 이상, 주당 약 30시간을 투자할 수 있고, 초기에는 무료 자료와 보유 장비를 활용하고 싶습니다. 방향이 정해지면 팀과 역할을 나눠 진행하겠습니다.
