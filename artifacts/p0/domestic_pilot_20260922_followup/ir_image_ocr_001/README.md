# 기존 SK IR의 이미지 페이지 OCR 보완

2026-09-22에 기존 SK하이닉스 IR PDF 10개의 이미지 전용 31쪽을 로컬에서 렌더링하고 OCR했다. 31쪽 모두 문자 후보를 반환했고 실행 오류는 없었다. **자동 인식 성공은 정확한 전사나 의미적 완전성 확인을 뜻하지 않는다.**

- 대상은 원본 PDF에서 기존 문자 추출 결과가 비어 있는 쪽이다. 기존 기록의 31쪽과 현재 탐지한 31쪽이 일치한다. 문자가 일부 있는 다른 쪽의 이미지까지 전부 검사한 결과는 아니다.
- 후보 단어는 409개다. Tesseract의 단어 confidence가 80 미만인 후보 304개, 40 미만인 후보 154개가 포함된다. confidence는 정답 확률이 아니며, 잡음·로고·배경을 잘못 읽은 후보도 있을 수 있다.
- AI가 대표 3쪽을 눈으로 확인했다. 이 3쪽은 장 구분 표지다. 2쪽에서는 주요 제목이 인식됐지만, 나머지 1쪽은 제목과 분기가 제대로 인식되지 않았다. 3쪽 모두 작은 한글 문구는 인식되지 않았다. 표본 밖의 28쪽도 같은 종류라고 확정하지 않았다.
- 자동 인식 후보를 숫자·기간·주장 근거 또는 정답 데이터로 승격하지 않았다. 사람의 전사 검증은 0쪽이며 의미적 완전성은 미확인이다.
- 원본 PDF 10개의 실행 전후 SHA-256은 모두 같고 기존 산출물은 바꾸지 않았다. 새 렌더와 OCR 텍스트의 해시·개수·좌표 범위 검사 31쪽은 통과했다.
- 렌더 이미지 31개와 인식 텍스트 JSON 31개는 `raw/`에만 있으며 62개 모두 Git 제외를 확인했다. 공개 파일에는 원문이나 인식 문장을 복제하지 않았다.

## 파일

| 파일 | 역할 |
| --- | --- |
| `summary.json` | 입력·출력 집계, 도구 버전, 한계 |
| `page_manifest.csv` | 원본 쪽 위치, 렌더/텍스트 해시, 단어 수, confidence, 검토 상태 |
| `document_page_check.csv` | 문서별 예상·실제 이미지 전용 쪽 수 |
| `source_preservation.csv` | 원본 PDF 실행 전후 해시 |
| `validation.json` | 텍스트/렌더 해시, 개수, 좌표, Git 제외 검사 |
| `visual_review.csv` | AI의 대표 3쪽 시각 검토와 인식 실패 기록 |
| `raw/*.png`, `raw/*.ocr.json` | 비공개 로컬 렌더, 단어·좌표·인식 문자열 및 대안 인식 시도 |

Tesseract 5.4.0의 기존 영문 모델과 PyMuPDF 1.28.0을 사용했다. 새 의존성 설치나 OCR 서비스로의 문서 전송은 없었다. 쪽 번호는 1부터, PDF 내부 쪽 인덱스는 0부터다. OCR 좌표는 200 DPI 렌더 이미지의 픽셀 기준이고 사람 판정은 별도로 남겨야 한다. 작은 글자·한글·배경이 있는 제목의 오류 때문에 이 결과만으로 재무 수치나 적용 기간을 확정할 수 없다.

재실행은 기존 출력을 덮어쓰지 않도록 **새 출력 경로**를 지정한다.

```powershell
python scripts/p01_ir_image_ocr.py --output-dir artifacts/p0/domestic_pilot_20260922_followup/ir_image_ocr_002
```

방법 문서: [PyMuPDF 이미지 렌더링](https://pymupdf.readthedocs.io/en/latest/recipes-images.html), [Tesseract 실행 옵션](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).
