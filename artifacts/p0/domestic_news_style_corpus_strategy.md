# P01 국내 뉴스 문체·표현 청킹 코퍼스 수집 전략

> 조사 기준일: 2026-09-20  
> 상태: 수집 방식 후보 검토안. 공급사 계약·샘플 검수 전이며, 특정 상품 구매를 확정한 문서가 아니다.

## 결론

P01의 목적에는 국내 기사 전체를 무차별 크롤링하는 방식보다 **저작권이 정리된 본문 API/파일 + 같은 기업 사건을 다룬 기사 묶음 + 검색형 표현 예문 뱅크**가 효율적이다.

1. 최신 기업 변화의 보도 방식은 한국언론진흥재단 **뉴스토어 인공지능용 뉴스데이터**를 1순위로 검토한다. JSON 또는 API로 본문을 받을 수 있고, 저장·분석·AI 학습을 허용하지만 기사 본문 외부 전송은 허용하지 않는다. RAG 상품은 구매 절차가 준비 중이므로 견적 단계에서 별도 확인이 필요하다.
2. **빅카인즈**는 기사 모집단, 사건별 기사 수, 매체 분포, 인용문·키워드 탐색에 사용한다. 무료 다운로드 본문은 저작권 보호를 위해 처음 200자만 제공되므로 문체 코퍼스 원문 공급원으로 쓰지 않는다.
3. 일반적인 한국 뉴스 문장 구조와 형태소 결합은 **국립국어원 모두의 말뭉치**와 **AI Hub 뉴스 데이터**로 먼저 학습·분석한다. 최신 기업 사건과 매체별 차이는 별도의 소규모 최신 라이선스 코퍼스로 보정한다.
4. 뉴스토어에 없는 핵심 매체가 반드시 필요할 때만 언론사와 직접 계약한다. 허가 범위가 없는 언론사 웹페이지 크롤링은 표본 확인용 보조 경로로 제한한다.
5. NAVER 뉴스 검색 API는 이 코퍼스의 후보에서 제외한다. 본문이 아니라 제목·원문 링크·검색 패시지만 주며, 현재 검색 API 약관은 결과와 파생물을 저장하거나 AI에 입력·학습·개선·평가·노출에 활용하는 것을 금지한다.

현재 P01 뉴스 자료는 삼성전자·SK하이닉스 공식 영문 Newsroom 4건, 본문 블록 186개뿐이다. 이는 언론사 기사도, 한국어 코퍼스도 아니므로 국내 언론의 말투나 청킹을 비교하는 근거로 사용할 수 없다. 기존 크롤러의 URL 정규화, robots 확인, 요청 간격, HTML 캐시·해시, XPath 블록, 날짜 충돌 검사는 재사용할 수 있다.

## 권장 수집 구조

### 1. 전체 기사 대신 사건을 먼저 고정한다

공시·IR·기업 공식 발표를 `event_anchor`로 삼아 다음 사건 유형을 균형 있게 고른다.

- 실적 상회·하회, 가이던스 상향·하향
- 제품 개발, 인증, 양산, 출하, 공급
- 투자, CAPEX, 공장·생산능력 증설 또는 축소
- 고객·계약·파트너십 변화
- 규제, 소송, 리콜, 정정·부인

각 사건에 `event_id`, 기업, 기준 발표시각, 공식 근거 문서, 핵심 변화, 방향·강도, 검색어를 부여한다. 기사는 기준 시각 전후 3~7일 창에서 모은다. 같은 사건을 보도한 기사끼리 비교해야 사건 고유 단어와 매체 말투를 분리할 수 있다.

### 2. 두 단계 표본을 사용한다

**P01 접근성 파일럿**

- 독립 사건 12~20개
- 사건당 공식 기준자료 1건 + 서로 다른 언론사 기사 3건 이상
- 총 언론 기사 36~60건 수준
- 목적: 매체별 본문 제공 범위, 메타데이터, 인용문, 중복률, 계약 조건 검증

**문체 비교 파일럿**

- 독립 사건 20~30개
- 사건 관련 한국어 기사 약 100건 + 변화가 없는 대조 기사 약 20건
- 5개 이상 매체, 매체당 15~20건, 매체마다 최소 10개 서로 다른 사건
- 기업·사건유형·시점을 매체 간 최대한 맞춘다.

이 수치는 연구에서 보장된 표본 크기가 아니라 P01의 접근·품질 검증을 위한 공학적 최소안이다. 이보다 작은 표본은 매체별 통계 결론이 아니라 예시 탐색으로 표시한다.

### 3. 매체 후보를 역할별로 고른다

뉴스토어 인공지능용 상품의 공식 판매 매체 목록에서 비용과 P01의 반도체·기업 변화 범위를 고려해 다음 순서로 검토한다.

- 1차 8개: 매일경제, 한국경제, 전자신문, 디지털타임스, 이데일리, 뉴스핌, EBN, 지디넷코리아
- 2차 4개: 아시아경제, 파이낸셜뉴스, 비즈워치, YTN
- 일반 프레이밍 보완: 중앙일보, 한겨레

접근성 파일럿은 1차 8개에서 시작해 사건당 최소 3개 매체를 맞춘다. 속보·해설·산업전문지 편중 여부를 본 뒤 2차 매체와 일반지를 추가한다. [뉴스토어 제공 언론사 표](https://www.newstore.or.kr/store/introduce/selectNewsMarketPartner.do)는 매체마다 판매 상품이 다름을 표시하므로, 견적서에서 AI용 본문 제공 여부를 다시 확인한다. 연합뉴스·뉴시스처럼 반드시 필요한데 뉴스토어 계약 범위에 없는 매체는 직접 계약 가능성을 먼저 확인한다.

## 본문을 어떻게 나눌 것인가

기사 한 건을 단일 텍스트로 처리하면 기업 보도자료 복사문, 취재원 발언, 기자 표현이 섞인다. 다음 단위를 각각 저장한다.

1. 제목·부제
2. 리드
3. 기자의 사실 서술
4. 직접인용
5. 인용 출처·전달 동사
6. 배경 설명
7. 기자·전문가 해석
8. 전망·우려·기대
9. 결론

각 블록과 문장에는 `speaker_type`, `source_type`, `discourse_role`, `stance_to_event`, `frame`, `certainty`, `temporal_frame`, `is_press_release_echo`를 붙인다. 직접인용과 기업 보도자료 복제 구간은 매체 문체 통계에서 분리한다.

한국어 청킹은 다음 세 층을 함께 둔다.

- 원문 surface와 어절
- 형태소 lemma/POS
- 연속 2~5 형태소 묶음과 3~5 token 창의 비인접 결합

모든 문장·형태소·chunk에는 원문 Unicode codepoint `start`/`end`를 보존한다. 우선 추출할 표현은 변화 주체·동사, 수치·증감·원인, 확실성·추정·유보, 기대·우려·평가, 인용 주체·전달 동사, 시간·전망 구간이다. 빈도만 비교하지 말고 같은 사건 묶음 안에서 매체별 log-likelihood, odds ratio, PMI와 문맥 예시를 함께 본다.

## 크롤링이 필요한 경우의 구현안

라이선스 API로 본문을 받을 수 없는 허가된 매체만 현재 `scripts/p01_news_body_crawl.py`를 확장한다.

1. 라이선스 API, 매체 RSS·sitemap에서 URL을 찾는다.
2. 정적 HTTP와 매체별 CSS/XPath adapter를 먼저 쓴다.
3. 미등록 매체는 Trafilatura를 fallback으로 사용한다.
4. JavaScript 실행 후에만 본문이 나타나는 페이지에만 Playwright를 사용한다.
5. 도메인별 동시 요청 1개, 2~5초 간격, `Retry-After`, 재시작 가능한 큐를 적용한다.
6. 최종 URL, 수집시각, HTTP 상태, raw HTML SHA-256, 본문 XPath, extractor 버전, 권리 근거를 저장한다.
7. paywall, 403, robots 차단, 명시적 수집 금지 페이지는 우회하지 않는다.

중복은 canonical URL·본문 SHA로 정확 중복을 잡고, 문장 shingle MinHash 또는 SimHash로 전재·제목 변경 기사를 묶는다. 공식 보도자료와 높은 유사도를 보이는 구간은 `press_release_echo`로 표시한다. 같은 사건이나 전재 묶음을 학습·평가 세트 양쪽에 나누지 않는다.

[Trafilatura 논문](https://aclanthology.org/2021.acl-demo.15/)은 본문·메타데이터 추출과 실제 웹 데이터 벤치마크를 제공하므로 미등록 도메인의 fallback 근거로 적합하다. 매체별 DOM adapter가 확보된 도메인에서는 원문 위치를 재현할 수 있는 adapter 결과를 우선한다.

## 크롤링보다 나은 분석 방식과 논문 근거

### 같은 사건끼리 맞춘 비교

[STEL](https://aclanthology.org/2021.emnlp-main.569/)은 문체 평가가 내용의 영향을 통제해야 한다고 지적하고, 단순 문자 n-gram·문장부호 빈도보다 문맥 표현 기반 측정이 더 잘 작동함을 보였다. [All Things Considered](https://aclanthology.org/2023.emnlp-main.957/)는 같은 이야기를 다룬 기사들을 정렬해 비교하면 포함·생략되는 사건과 매체 차이를 더 잘 포착한다고 보고했다. 따라서 임의 기사 대량 수집보다 `같은 사건 × 여러 매체` 표본이 이 목적에 더 직접적이다.

### 기사 전체가 아니라 역할별 segment 비교

[K-News-Stance](https://aclanthology.org/2025.emnlp-main.778/)는 한국 뉴스 2,000건, segment 수준 주석 21,650개를 구축하고 리드·인용 같은 핵심 segment의 판단을 종합하는 방식이 기사 전체 단위 기준보다 우수하다고 보고했다. [QuoteCSE](https://aclanthology.org/2023.findings-eacl.52/)는 한국 뉴스에서 제목의 인용 표현이 본문 발언의 맥락을 바꿀 수 있음을 다뤘다. 직접인용, 제목 재구성, 기자 서술을 분리해야 하는 근거다.

### 긍정·부정 대신 무엇을 강조했는지 기록

[The Media Frames Corpus](https://aclanthology.org/P15-2072/)는 여러 이슈의 뉴스에 공통 frame을 주석해 매체가 같은 사안을 어떤 관점으로 구성하는지 분석했다. P01에서는 단순 감성 점수만 두지 않고 경제효과, 책임, 갈등, 공정성, 위험·안전처럼 강조된 관점을 사건별 비교축으로 둔다. 이 논문은 영어권 자료를 사용했으므로 한국 기사에는 소규모 수동 검증을 먼저 한다.

### 한국어 형태소와 비인접 결합

[Retrieving Collocations From Korean Text](https://aclanthology.org/W99-0610/)는 한국어의 교착성과 비교적 자유로운 어순 때문에 POS가 붙은 형태소와 비인접 bigram을 사용했다. 따라서 공백 기준 n-gram만으로 `말투 및 단어 청킹`을 만들지 않고, 어절·형태소·POS·비인접 결합을 함께 보존한다.

### 큰 코퍼스를 모두 쓰지 않고 목표 분포에 맞춰 고르기

[DSIR](https://proceedings.neurips.cc/paper_files/paper/2023/hash/6b9aa8f418bde2840d5f4ab7a02f663b-Abstract-Conference.html)은 작은 목표 표본과 가까운 문서를 대형 원시 코퍼스에서 importance resampling으로 고르는 방법을 제시한다. P01에서는 공식 사건 anchor와 수동 검수 기사로 목표 분포를 만든 뒤, 나머지 후보를 기업·사건유형·표현 분포가 가까운 순으로 선택하는 데 적용할 수 있다.

### 파인튜닝보다 검색형 예문 뱅크를 먼저 사용

[Data-to-Text Generation with Style Imitation](https://aclanthology.org/2020.findings-emnlp.144/)은 기존 문장을 soft template로 사용해 내용 충실도와 문체 제어를 함께 다뤘다. 뉴스 도메인 자체의 실험은 아니므로 직접적인 성능 보장은 아니지만, P01에서는 대규모 본문을 모델에 학습시키기 전에 사건유형·문단역할·매체가 맞는 5~10개 예시를 검색해 표현 후보만 참고하는 설계가 더 작고 감사 가능하다.

## 결과물 형태

원문 저장소와 분석 결과를 분리한다. 외부로 전달하는 것은 계약이 허용한 파생 통계와 짧은 검토 예시뿐이며, 전체 기사 본문은 내보내지 않는다.

권장 style bank 레코드:

```text
event_id, article_id, outlet, genre, published_at,
segment_role, speaker_type, source_type, stance_to_event,
frame, certainty, temporal_frame, evaluative_predicate,
surface, lemma_pos_chunks, char_start, char_end,
source_url, rights_basis, extractor_version
```

기사 생성·요약 단계에서는 `기업 + 사건유형 + 변화 방향 + 문단 역할`로 예문을 검색한다. 검색된 예문은 표현 후보와 금지된 과장·단정 여부를 검토하는 근거로 사용하고, 기사 문장을 길게 복제하지 않는다.

## 파일럿 품질 기준

- 정적 페이지 본문 추출 성공률 90% 이상
- 원문 XPath 또는 API 원문 위치가 있는 블록 90% 이상
- XPath와 chunk offset 원문 round-trip 100%
- 발행일 근거 기록 95% 이상, 날짜 충돌은 전부 검토 대기 처리
- 최소 20개 기사 수동 감사에서 본문 precision 95% 이상, recall 90% 이상
- 제목·리드·본문·인용이 균형 잡힌 200문장 청킹 감사
- 임시 기준으로 chunk boundary exact F1 0.90 이상
- 사건 trigger, 수치, 단위, 기간 span의 원문 round-trip 100%

## 다음 실행 순서

1. 뉴스토어에 인공지능용 뉴스데이터 샘플과 견적을 요청한다. 기간, 6~12개 매체, 전체 본문, 제목, 발행시각, 기자, 원문 URL, 뉴스 ID를 요구한다.
2. 견적 질의에 외부 클라우드 LLM 처리 가능 여부, embedding/vector 저장, 파생 chunk 저장, 보유기간, 내부 사용자 수, 분석 결과 외부 공개 범위를 명시해 답변을 받는다.
3. 빅카인즈에서 12~20개 기준 사건별 기사 수와 매체 분포를 먼저 산출한다.
4. 라이선스 샘플로 36~60건 접근성 파일럿을 수행한다.
5. 본문·메타데이터·중복·인용 분리·형태소 offset을 감사한 뒤 100+20건 문체 비교 파일럿으로 확장한다.
6. 계약되지 않은 웹 본문 수집은 필요한 매체와 사건에만 별도 권리 근거를 기록하고 진행한다.

뉴스토어 계약이 성립하지 않으면 `모두의 말뭉치/AI Hub 기반 일반 표현 뱅크 + 직접 계약한 2~3개 매체의 최신 사건 표본`으로 축소한다. 권리 근거 없는 전면 크롤링으로 대체하지 않는다.
